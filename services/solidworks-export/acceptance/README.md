# Проверка EASM на Windows

Каталог `acceptance` поставляется вместе с `server.py` и `prepare.py`.
Для выдачи EASM на исполнителе нужны eDrawings x64 с библиотекой
`eDrawings.Interop.EModelViewControl.dll`, Windows PowerShell и компилятор
.NET Framework 4.x. Рабочий сервер проверен с eDrawings 2023.

После экспорта очередь открывает EASM в eDrawings и ждёт события завершения
загрузки. Для новых сборок она сравнивает имена всех физических экземпляров
первого уровня с результатом повторного открытия упакованной сборки в SOLIDWORKS.
В число узлов дерева eDrawings входят также корень и вложенные документы насосов.
Журнал проверки находится в `check-edrawings.log` в каталоге задания.
Если проверка не проходит, пользователь может ещё раз выбрать EASM, используя
ту же готовую сборку. ZIP остаётся доступным.

Параметр `-PublishExe <путь к новому .exe>` публикует модель вместе с просмотрщиком для Windows x64. Его можно сочетать с `-ExpectedNames`. Открывается готовый EASM; приложение ждёт событий загрузки и сохранения от eDrawings. Параметр `-PreviewJpg` сохраняет отдельное изображение и не используется вместе с `-PublishExe`.

Проверка 02.11.2026: из готового EASM задания `e4bbb6bc-1057-4192-8615-84320f48915b` получен автономный EXE размером 42 129 381 байт. При запуске он извлёк собственный EModelViewer и передал ему вложенный EASM. При независимом открытии именно вложенной модели eDrawings подтвердил имена 1235 включённых экземпляров (1236 узлов с корнем). Через рабочую очередь дополнительно проверены скачивание EXE и повторный запрос без изменения времени записи EASM, ZIP и проверенной сборки.

В именах файлов и экземпляров десятичные запятые заменяются точками. Название из
спецификации с исходной пунктуацией хранится в свойстве документа «Наименование».
