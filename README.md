# Pump Station Calculator

Приложение для подбора насосов, расчёта обвязки и подготовки спецификации насосной установки.

В **full** расчёт выполняется в рабочем пространстве подключённого продукта. Стандартный продукт «Насосная установка» связывает настройки, подбор насосов, кривые и карточки, расчёт DN, коллекторы, спецификацию, раму и 3D-компоновку. Проект закрепляет версию алгоритма и снимки источников. Правка графа и управление публикациями доступны администратору. Панель **☰ Pump-ик** справа в шапке помогает разобраться с текущими результатами, правилами и каталогами.

В **beta** доступно отдельное рабочее пространство с подбором основного контура, кривой, карточкой насоса, просмотром комплектующих и чатом AI-assistant. Раскладка и ввод сохраняются в браузере. Возможности каждого профиля и уровней доступа описаны в документации.

## Сборка и запуск

Требуются Git, Node.js 22.13 или новее и npm. Для локальной full-версии нужны PostgreSQL, локальная D1, источники каталога и настроенный профиль Windows. Конвертер CAD и Windows-исполнитель SOLIDWORKS настраиваются для соответствующих функций.

Все команды выполняются из корня исходников приложения.

| Команда | Результат |
| --- | --- |
| `npm ci` | Установить зависимости по lock-файлу |
| `npm run dev -- --port 3000` | Запустить разработку, по умолчанию в профиле full |
| `npm run build:full` | Собрать full с локальной службой расчётов |
| `npm run build:beta` | Собрать beta. Обычный `npm run build` по умолчанию также собирает beta |
| `npm run start:local` | Запустить собранную full из настроенного профиля Windows |
| `npm run preview:beta` | Запустить отдельный локальный Worker beta, по умолчанию на порту 3010 |

Сборка формирует каталожные данные и справку, затем записывает Worker и клиент в `dist/`. Профиль виден в `dist/release.json` и по `GET /api/release`. Доступ к функциям определяется профилем сборки и ролью вошедшего пользователя.

Для первого локального запуска установите зависимости, соберите full, настройте базы и примените миграции по инструкции. Для работающего экземпляра используйте отдельный снимок релиза и сохраняйте прежние каталоги состояния. [Настройка локального хранилища и запуск full](docs/local-project-storage.md)

Нодовый каталог насосов читает SQLite-файл каталога v2. Для полного локального предпросмотра путь можно задать через `NODE_PUMP_CATALOG_PATH`. Проект работает с закреплённым снимком каталога, а обновление назначается отдельно в «Расчёт → Действия продукта». Для beta используется каталог `public/pumps.json` с дополнениями из базы ручных насосов. [Нодовый подбор насосов](docs/node-pump-selection-manual.md), [источники поставляемого каталога beta](data/pump-catalog/README.md)

Локальный full и предпросмотр beta загружают настройки Pump-ика из игнорируемого файла `.env.ai.local`. В среде Worker используйте серверные переменные и секреты. [Подключение Pump-ика](docs/ai-assistant.md), [отдельный запуск beta](docs/beta-0.1.md)

## Структура

| Путь | Содержимое |
| --- | --- |
| `app/node-tools/` | Рабочее пространство продукта, редактор, исполнитель графов и привязки к источникам |
| `app/model-editor/`, `app/frame-calculation/` | Компоновка, расчёты рам и монтажные данные |
| `app/api/`, `worker/`, `build/` | Серверные маршруты, Worker и профили выпуска |
| `drizzle/` | Миграции D1, включая библиотеку алгоритмов, снимки каталогов и каталог рам |
| `services/local-storage/` | PostgreSQL, сохранение проектов и локальные службы каталогов |
| `data/`, `public/` | Каталожные данные, изображения и поставляемые ресурсы |
| `docs/`, `tests/` | Руководства, технические материалы и проверки |

## Проверки

| Команда | Назначение |
| --- | --- |
| `npm run typecheck` | Типы приложения и Worker |
| `npm run lint` | ESLint |
| `npm test` | Сборка и все JavaScript-тесты |
| `node scripts/build-help-content.mjs --check` | Проверка справки |
| `node scripts/build-assistant-runtime.mjs --check` | Проверка базы знаний Pump-ика |
| `npm run build:full` + `node tests/node-tools-full.mjs` | HTTP-проверка нодового full |
| `npm run db:generate` | Сгенерировать миграции после изменения схемы |
| `npm run cf-typegen` | Обновить типы Cloudflare после сборки |

Python-проверки CAD используют окружение [конвертера моделей](docs/model-converter.md).
