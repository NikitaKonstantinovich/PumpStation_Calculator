# Pump Station Calculator

Веб-приложение для подбора насосов и комплектации насосных установок.
Полная версия объединяет подбор по рабочей точке, гидравлические кривые,
карточки насосов, расчёт DN, коллекторы, шкафы управления, спецификацию,
расчёт вставок и 3D-редактор. Проекты и расположение окон сохраняются;
поддерживаются второй контур, светлая и тёмная темы, сетка и свободные окна.

Документация актуализирована **29.10.2026** для текущей версии исходников.
Версия пакета — `0.1.0-beta.1`. Стек: React 19, TypeScript, vinext/Vite,
Cloudflare Workers/D1, Drizzle ORM и Three.js.

## Полная версия и beta

| Режим | Команда | Возможности |
| --- | --- | --- |
| Разработка, `full` по умолчанию | `npm run dev -- --port 3000` | Полное рабочее пространство с ограничениями по роли |
| Сборка `full` | `npm run build:full` | Полная версия для запуска через Worker/D1 |
| Сборка `beta` по умолчанию | `npm run build` или `npm run build:beta` | Подбор, кривая, карточка насоса и база комплектующих |
| Предпросмотр beta | `npm run preview:beta` | Собранная beta на `localhost:3010`, отдельная локальная D1 |

В beta остальные инструменты видны, но заблокированы для всех ролей.
Администратору дополнительно доступен «Список пользователей». Профиль задаётся
при сборке; роль, URL и localStorage не включают полную версию. Профиль и версия
доступны через `GET /api/release` и в `dist/release.json`.
[Ограничения beta и создание тестировщиков](docs/beta-0.1.md).

## Возможности полной версии

- Подбор по фактической рабочей точке, цене и фильтрам; рабочие и резервные
  насосы, отдельный подбор второго контура.
- Единый пересчёт насосов, шкафов, коллекторов и обвязки при изменении проекта.
  Техническая готовность, полнота состава и полнота стоимости проверяются
  отдельно; устаревшие результаты исключаются из актуального итога.
- Расчёт и подбор сохранённых вставок, состав деталей и работ, уплотнения,
  крепёж, окраска Ст20, проверка DN/PN и источников размеров.
- КИП по схеме управления, бак 8/50/100 л, заглушки, разделительные затворы
  и реестр занятых портов коллекторов.
- Выбор конструкции и высоты рамы по массе самого тяжёлого отдельного насоса
  активных контуров. Длина, ширина, монтажные отверстия и стоимость ещё требуют
  уточнения; выбранный профиль рамы не означает готовую конструкцию.
- 3D-сборки насосных ветвей, составные вставки, коллекторы, виброкомпенсаторы,
  кронштейны и концевые выключатели. Ручная компоновка, измерения, привязки,
  отмена/повтор и сохранение сцены в проекте.
- CSV/XLSX спецификации с замечаниями, количествами, ценами и итогами.
  CSV использует UTF-8 с BOM, разделитель `;` и десятичную запятую.
- Диагностика из всех инструментов, включая закрытые окна. Двойной щелчок
  или Enter по замечанию открывает и выделяет источник проблемы.

Роли: `base`, `plus`, `pro`, `admin`; сервер проверяет права на проекты,
настройки и каталоги. [Матрица доступа](docs/user-administration.md).
Расчёт комплектующих открывается из меню администратора в профиле `full`.

## Требования и структура

- Git, Node.js **>=22.13.0**, npm.
- Python 3 для импортёров, Python-тестов и необязательного сервиса CAD.
  Для обычного запуска веб-приложения Python не требуется.
- Место для зависимостей, сборки и изображений каталога; исходные изображения
  занимают около 600 МБ.

Все команды выполняются из корня репозитория: в рабочем каталоге владельца
это `E:\PumpStation_Calculator\frontend`. В чистом клоне корнем будет папка,
в которую вы клонировали репозиторий.

| Путь | Содержимое |
| --- | --- |
| `app/`, `app/api/` | Интерфейс, расчёты и серверные обработчики |
| `app/model-editor/` | 3D-редактор, сборки и геометрия |
| `data/`, `public/` | Исходные и рабочие каталоги, изображения и модели |
| `db/schema.ts`, `drizzle/` | Схема D1 и миграции `0000`–`0010` |
| `worker/`, `build/` | Worker, профили сборки и обработка ресурсов |
| `scripts/`, `services/` | Импорт, подготовка CAD и локальные серверы |
| `tests/`, `docs/` | Проверки и подробные инструкции |

Внешние `database/`, `Equipment/`, `reference-calculator-nu/` используются
для повторного импорта и подготовки исходных CAD. Они не требуются для обычного
запуска с поставляемыми каталогами. Копии библиотечных CAD и конвертер
настраиваются отдельно: [3D-редактор](docs/3d-editor.md),
[подготовка моделей](docs/model-converter.md).

## Первый запуск с новой локальной базой

```powershell
git clone https://github.com/NikitaKonstantinovich/PumpStation_Calculator.git frontend
Set-Location frontend
npm ci
npm run build:full
```

Сборка запускает `prebuild`: формирует каталог коллекторов, источник вставок,
дополнения карточек и индекс патрубков. В `dist/` появляются клиент, Worker
и конфигурация `dist/server/wrangler.json`.

D1 хранит пользователей, сессии, проекты и серверные каталоги. Локальная D1
расположена в `.wrangler/state/`; она не является `database/pumps.sqlite`.
Следующий блок предназначен **только для новой пустой локальной D1**:

```powershell
$env:WRANGLER_WRITE_LOGS = "false"
Get-ChildItem -LiteralPath drizzle -Filter *.sql | Sort-Object Name | ForEach-Object {
    node node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file $_.FullName
    if ($LASTEXITCODE -ne 0) { throw "Не удалось применить миграцию $($_.Name)" }
}
$env:PSC_RELEASE_PROFILE = "full"
npm run dev -- --port 3000
```

Откройте [http://localhost:3000/](http://localhost:3000/), зарегистрируйтесь и
подтвердите адрес. Без почты в полной версии на hostname `localhost`
показывается тестовая ссылка подтверждения; на `127.0.0.1` и сетевом IP её нет.

Для повторного запуска с существующей базой достаточно последних двух команд.
Не применяйте все SQL повторно: сначала проверьте схему и сделайте резервную
копию через SQLite backup API; применяйте только отсутствующие изменения.
API авторизации может дополнить свои таблицы, но не заменяет миграции каталогов.
[Разбор ошибок D1/503](docs/collector-constructor.md).

## Запуск собранной полной версии на порту 3000

При уже подготовленной `.wrangler/state`:

```powershell
npm run build:full
node scripts/snapshot-local-full.mjs work/local-full-2026-10-29/dist
node scripts/preview-full.mjs --build-dir work/local-full-2026-10-29/dist --state-dir .wrangler/state --port 3000
```

Сервер слушает `127.0.0.1:3000`; открывайте `http://localhost:3000/`.
Остановка в терминале — `Ctrl+C`. Снимок не должен существовать: при следующем
обновлении выберите новый путь, чтобы не перезаписать работающую сборку.
Сервер не применяет миграции. Крупные модели читает из `public/model-assets`
через авторизованный binding `ASSETS`, поэтому эта папка нужна рядом с исходниками.

`preview-full.mjs` принимает секреты почты и `MODEL_CONVERTER_URL` /
`MODEL_CONVERTER_TOKEN` из окружения процесса. Он не загружает `.env.local`
или `.dev.vars` самостоятельно. Профиль dev можно переключить через
`$env:PSC_RELEASE_PROFILE = "beta"`; вернуться — через значение `"full"`.

Обычный `npm start` запускает Node-сервер vinext, но сам не создаёт binding D1.
Для работы с данными используйте dev с Cloudflare Vite-плагином или описанный
предпросмотр Worker. [Отдельное размещение beta на Windows](docs/beta-0.1-windows-hosting.md).

## Почта и сохранность данных

Для dev без отправки писем дополнительные env-файлы не нужны. Для почты
скопируйте `.env.example` в `.env.local`, задайте `RESEND_API_KEY`, `EMAIL_FROM`
и `APP_BASE_URL`, затем перезапустите dev-сервер. В Worker эти параметры
нужно передать его окружению. В beta восстановление пароля требует почты;
администратор также может задать новый пароль через список пользователей.

`.wrangler/state`, env-файлы, локальные CAD-кэши, резервные копии и журналы
не входят в Git. Не удаляйте состояние D1 при очистке сборки. `git push`
передаёт код и каталоги, но не переносит пользователей, проекты и базу,
не применяет удалённые миграции и не обновляет работающий сервер.

## Каталог и правила подбора

В каталоге **5 856 моделей шести производителей**, **5 039** доступны для
подбора, **54 423** точки Q/H. Включены 98 LEO XST, из них 61 модель 50 Гц
доступна для подбора. Рабочие данные — `public/pumps.json`; происхождение,
снимки и отчёт объединения — `data/pump-catalog/`.

Подбор использует PCHIP без экстраполяции. График дополнительно поддерживает
ломаную и полиномиальное сглаживание; изменение графика не меняет метод
подбора. Для параллельных насосов суммируется расход. График выгружается
в PNG, JPEG и PDF.

Сортировка «По рабочей точке» сравнивает фактическое пересечение характеристик
насоса и системы с заданной точкой: `D = hypot(ΔQ, ΔH)`, отклонения — в процентах.
При сортировке «По цене» первыми идут насосы, у которых оба отклонения находятся
от −2% до +15% включительно, затем остальные с доступной точкой, затем без неё.
Внутри группы учитываются цена со скидкой, близость точки и ID. Неизвестная
цена идёт после известных в своей группе. Показываются первые 100 результатов.

Не у всех моделей есть индивидуальные чертежи, цены и монтажные размеры.
Справочный лист серии обозначается как справочный; неизвестные данные не
заменяются данными другого исполнения. [Источники и повторный импорт](data/pump-catalog/README.md).
Не запускайте старый `database/export_pumps_for_frontend.py` поверх текущего
`public/pumps.json`: он перезапишет объединённый каталог прежней базой.

## Команды проверки

| Команда | Назначение |
| --- | --- |
| `npm run prebuild` | Пересобрать производные JSON без сборки приложения |
| `npm run typecheck` | Проверить браузерный и серверный TypeScript |
| `npm run lint` | ESLint без допустимых предупреждений |
| `npm test` | Собрать приложение и запустить все `tests/*.test.mjs` |
| `npm run test:unit` | Только тесты коллекторов |
| `npm run check` | Типы, ESLint, сборка и все JS-тесты |
| `python -m unittest discover -s tests -p 'test_*.py'` | Python-импортёры и подготовка моделей; полный набор требует OpenCascade |
| `npm run cf-typegen` | После сборки обновить типы Cloudflare |
| `npm run db:generate` | Сгенерировать миграции после изменения схемы; не применить их |

Прямой `node --test tests/*.test.mjs` требует свежей сборки: тесты HTML читают
`dist/server/index.js`. Для полного Python-набора используйте окружение с
`services/model-converter/requirements.txt`, описанное в
[инструкции конвертера](docs/model-converter.md). Часть CAD-проверок пропускается
без OpenCascade, но тесты нативных воротников требуют его явно. Часть проверок
также использует внешнюю локальную SQLite.
Исторические результаты и текущие проверки: [состояние на 29.10.2026](docs/current-state-2026-10-29.md).
