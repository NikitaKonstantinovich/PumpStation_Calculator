# Подготовка браузерных 3D-моделей

В **3D-модель → 3D редактор** нажмите **Подготовить 3D-модели спецификации** рядом
с «Обновить состав». Нужны вход в приложение и подключённый сервис конвертации.
Обрабатывается текущая спецификация: насосы, арматура, шкафы и другие позиции
с привязанным STEP. Выбор насоса только в подборе не добавляет его в очередь.

Поиск читает фактический SHA-256 исходных STEP и объединяет одинаковые файлы,
включая разные ID оборудования с одинаковым содержимым. Актуальные STL повторно
не конвертируются. Дата изменения, размер и имя не заменяют проверку хеша.
Ранее подготовленные `public/model-assets` используются при совпадении SHA-256.

При поиске шкала неопределённая. Процент конвертации равен
`100 × завершённые задания / задания, требующие конвертации`; ошибки входят
в число завершённых. Для отдельного STEP показывается индикатор выполнения без
внутреннего процента. «Обновление сцены» означает загрузку и разбор готовых STL.
Ошибки конвертации и загрузки сцены различаются; обе операции можно повторить.
В итоге N/M — число уникальных моделей, K — число позиций без исходника,
а не число физических экземпляров. Повторная попытка показывает итог этой попытки.

Положения, повороты, видимость, прозрачность, фиксация, ручные трубы и параметры
рамы сохраняются. Подготовленные ресурсы обновляются также в истории
отмены/повтора. Новое оборудование размещается рядом с установкой для ручной
компоновки. Автоматическая врезка арматуры пока не поддерживается. Ограничение
редактора — 500 компонентов. Перед перезагрузкой страницы дождитесь обычного
сообщения приложения «Все изменения сохранены» либо нажмите «Сохранить».

Закрытие инструмента и страницы не останавливает задание. Статус восстанавливается
по пользователю и ID проекта. Результат другого проекта не применяется. Задание
использует снимок спецификации на момент запуска; последующие изменения попадут
в следующий запуск. Для одного пользователя/проекта допускается одно активное
задание, включая разные вкладки.

## Устройство

React/Three.js остаются в приложении. `/api/model-preparation` проверяет сессию
и пересылает короткие запросы Python-сервису. Статус опрашивается раз в секунду,
при потере связи — раз в три секунды. Workers не запускают Python/OCP и не держат
запрос на время конвертации. Секрет сервиса не попадает в браузер.

Сервис использует стандартный HTTP-сервер Python, SQLite и один фоновый worker.
Каждый STEP обрабатывается отдельным процессом с тайм-аутом 600 секунд. Ошибка,
авария OCP или тайм-аут одного файла не останавливают очередь. После перезапуска
незавершённые задания снова проверяют исходники и используют сохранённые копии.
Запускайте **один экземпляр на каталог состояния**; несколько реплик с общей
SQLite не поддерживаются.

STL и индекс хранятся в `<state>/assets` и `<state>/jobs.sqlite`. Приложение
выдаёт файлы через `/api/model-preparation/assets/model-<sha256>-v1.stl`.
Кэш моделей каталога общий для авторизованных пользователей, задания изолированы
по пользователю. Каталог состояния должен находиться на постоянном диске.
Автоматическая очистка старых заданий и версий STL пока не реализована.

## Локальный запуск, Windows

Нужны Python 3.13, Node согласно `package.json` и исходная библиотека рядом с
`frontend`. В PowerShell:

```powershell
Set-Location E:\PumpStation_Calculator\frontend
py -3.13 -m venv .venv-models
.\.venv-models\Scripts\python.exe -m pip install -r services\model-converter\requirements.txt
```

Добавьте в `.dev.vars` две строки, сохранив другие настройки. Создайте случайный
ключ командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`:

```dotenv
MODEL_CONVERTER_URL=http://127.0.0.1:8766
MODEL_CONVERTER_TOKEN=<случайный ключ не короче 24 символов>
```

`.dev.vars`, окружение и состояние сервиса исключены из Git. Загрузите тот же
ключ в процесс сервиса и запустите его:

```powershell
Set-Location E:\PumpStation_Calculator\frontend
$env:MODEL_CONVERTER_TOKEN = ((Get-Content .dev.vars | Where-Object { $_.StartsWith('MODEL_CONVERTER_TOKEN=') }) -replace '^MODEL_CONVERTER_TOKEN=','')
.\.venv-models\Scripts\python.exe services\model-converter\server.py --root E:\PumpStation_Calculator --state E:\PumpStation_Calculator\frontend\.model-converter --port 8766
```

Оставьте терминал работающим. Во втором терминале запустите `npm run dev`.
Если dev-сервер уже работал при создании `.dev.vars`, перезапустите его.
Откройте проект, войдите в приложение и нажмите кнопку подготовки.
В текущей рабочей копии настройки подключения уже записаны в игнорируемый `.dev.vars`.

Сервис по умолчанию слушает только `127.0.0.1`. Поддержаны `--port`, `--state`,
`--root`, `--registry`, `--timeout`. Без OCP доступны статусы и готовые копии,
а конвертация завершится ошибкой зависимости. Запускайте Python именно из venv.

## Библиотека и арматура

Насосы подключаются из `Equipment/Pumps/3D_Normalized/normalization-index.json`
(в исследованной библиотеке 687 профилей). Исходники находятся вне Git-репозитория
`frontend`; для серверного запуска скопируйте их отдельно. Индексированных STEP
арматуры в исследованной библиотеке не обнаружено. Случайные похожие файлы
программа не подставляет.

Для любого другого оборудования создайте `Equipment/model-library.json`.
Шаблон: [library.example.json](../services/model-converter/library.example.json).
Путь и ID в примере заменяются фактическими значениями:

```json
{
  "version": 1,
  "models": [{
    "key": "equipment:ID_ИЗ_СПЕЦИФИКАЦИИ",
    "source": "Equipment/Valves/valve.step",
    "units": "mm",
    "ports": [
      { "id": "inlet", "point": [0, 0, 0], "axis": [-1, 0, 0], "provisional": true },
      { "id": "outlet", "point": [200, 0, 0], "axis": [1, 0, 0], "provisional": true }
    ],
    "mapping": "manual_catalogue_link",
    "warnings": ["Соответствие исполнению каталога требует проверки"]
  }]
}
```

Ключ `pump:<equipmentId>` используется для насосов, `equipment:<equipmentId>` —
для остальных позиций. ID берётся из `station-spec.items[].equipmentId`, название
не используется для угадывания модели. Разные ID могут ссылаться на один STEP.
Реестр перечитывается при каждом запуске; `--registry` задаёт альтернативный путь.

`source` — относительный путь внутри `--root`, форматы `.step`/`.stp`.
Пути из браузерного запроса не принимаются. Используйте выделенный корень
библиотеки; реестр является доверенной настройкой администратора.
Отсутствие связи или файла учитывается отдельно от повреждения STEP.

Начало координат и ориентация STEP сохраняются. OCP читает единицы файла и переводит
длины в миллиметры (`SetSystemLengthUnit(1.0)`); STL всегда в мм. `ports.point`
задаётся **в миллиметрах в той же системе координат**, `axis` — наружу из патрубка.
Центрирование и растяжение до каталожных габаритов не выполняются. Нормализованные
насосы сохраняют вход в начале координат и Z вверх. Общая модель должна уже иметь
нужную ориентацию; сервис её не угадывает. Если указан `sourceHash` и файл изменился,
точки сохраняются с предупреждением о повторной проверке. Предупреждения насосов
о расхождении габаритов и соответствии каталогу сохраняются.

## Опубликованная версия, Cloudflare Workers

1. Разместите сервис на отдельном сервере с постоянным диском. Скопируйте
   `frontend/services/model-converter`, `frontend/scripts/model_assets.py`,
   при необходимости `frontend/public/model-assets`, сохранив расположение этих
   папок. Отдельно скопируйте библиотеку `Equipment` и реестр.
2. Создайте Python 3.13 venv, установите тот же `requirements.txt`. Например,
   код — `/opt/pump-converter/frontend`, библиотека — `/srv/pump-library`,
   состояние — `/var/lib/pump-model-converter`:

```sh
python3.13 -m venv /opt/pump-converter/.venv
/opt/pump-converter/.venv/bin/pip install -r /opt/pump-converter/frontend/services/model-converter/requirements.txt
export MODEL_CONVERTER_TOKEN='<тот же случайный ключ, что у Worker>'
/opt/pump-converter/.venv/bin/python /opt/pump-converter/frontend/services/model-converter/server.py --root /srv/pump-library --state /var/lib/pump-model-converter --host 127.0.0.1 --port 8766
```

3. Для постоянной работы настройте systemd или службу Windows с указанной
   командой запуска, перезапуском при сбое и защищённым файлом переменных.
   Процессу нужны чтение библиотеки и запись каталога состояния.
4. Настройте HTTPS reverse proxy с действительным сертификатом, например
   `https://cad.example.com`. Nginx в HTTPS server block:

```nginx
location /v1/ {
    proxy_pass http://127.0.0.1:8766;
    proxy_set_header Authorization $http_authorization;
    proxy_set_header X-Model-Owner $http_x_model_owner;
    client_max_body_size 500k;
    proxy_read_timeout 20s;
}
```

   Публичный доступ к порту 8766 не нужен. CORS не требуется: браузер обращается
   к своему API, а Worker — к сервису. URL должен быть конечным, без редиректов.
5. В настройках **опубликованного Worker**, Variables and Secrets, задайте
   `MODEL_CONVERTER_URL=https://cad.example.com` и секрет `MODEL_CONVERTER_TOKEN`.
   Для обычного Wrangler-развёртывания после `npm run build`:

```sh
npx wrangler secret put MODEL_CONVERTER_URL --config dist/server/wrangler.json
npx wrangler secret put MODEL_CONVERTER_TOKEN --config dist/server/wrangler.json
```

   Проверьте, что config относится к нужному Worker. При публикации платформой
   хостинга задайте переменные её средствами. Не используйте `VITE_*` или публичные
   JSON для секрета. `localhost` опубликованного Worker не указывает на ваш компьютер;
   требуется доступный Worker HTTPS-адрес.

Опубликованная версия в этой задаче не развёртывалась. Локальная цепочка проверена
через тот же Worker runtime: браузер → API → Python → OCP → STL → сцена.

## Проверки

```powershell
npm run check
python -X utf8 -m unittest discover -s tests -p test_model_converter.py -v
.\.venv-models\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_model_converter_ocp.py -v
```

Первый Python-набор проверяет очередь без OCP. Второй реально читает STEP,
проверяет миллиметры/метры, положение геометрии и повреждённый файл.
CLI статической подготовки сохранён: `python scripts/prepare-model-assets.py
--pump-id 9 90 318`. Он использует общий `scripts/model_assets.py`.

Вся локальная библиотека STEP, включая позиции без связи с каталогом,
готовится командой `python -X utf8 scripts/prepare-equipment-library.py`.
Параметры `--root`, `--output`, `--state`, `--workers` (1–8) и `--timeout`
позволяют выбрать источник, выход, кэш, параллельность и время на одну модель.
Непривязанные модели доступны через «＋ Из библиотеки» для ручной компоновки.
После пакета обновляются готовые профили насосов и подтверждённые связи
`Equipment/model-library.json`. Сервис использует эти копии, проверяя хеши;
повторная конвертация для них не требуется. Подготовка отдельных насосов
сохраняет профили прочего оборудования и общие копии сеток.

Дополнительные проверки:

```powershell
node --test tests/model-library.test.mjs tests/model-preparation.test.mjs
python -X utf8 -m unittest discover -s tests -p test_equipment_library.py -v
```

Последний тест использует настоящий OCP: миллиметры и смещённую геометрию,
дубли, повреждённый STEP, повторный запуск и восстановление испорченной сетки.

«Сервис не подключён» означает отсутствие серверных переменных. «Недоступен» —
сетевую ошибку или остановленный сервис; принятое задание не потеряно. При ошибке
токена проверьте одинаковое значение в обоих процессах. При ошибке загрузки STL
проверьте сервис и сохранность `<state>/assets`.
