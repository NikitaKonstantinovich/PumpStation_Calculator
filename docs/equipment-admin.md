# Административная база комплектующих

В full и beta пункт бургер-меню **База комплектующих** открывает
`/?view=equipment-admin`. Раздел и все `/api/admin/equipment` API доступны
только admin. Общие каталоги калькулятора сохраняют прежние права чтения.

Вкладки формируются из реальных категорий: насосы (включая ручные), полный
импорт комплектующих, шкафы, электрические компоненты, сохранённые коллекторы
и вставки. Действующий импорт D1 имеет приоритет; при отсутствии импорта
используется полный поставляемый каталог с дополнениями. Неактивные записи
включены. Профиль без SQL-конфигуратора шкафов использует поставляемые
`control-cabinets.json` и `control-cabinet-database.json`, как обычное рабочее
пространство. При наличии SQL-каталога его записи имеют приоритет. Отсутствие
всех трёх необязательных таблиц определяется по схеме; частичная установка
или ошибка чтения SQL не подменяется пустой таблицей.

Поиск, сортировка, фильтр характеристики, состояния и наличия файлов работают
по выбранной категории. На странице 40 строк. Меню «Столбцы» открывает любой
скалярный параметр; нажатие названия раскрывает все вложенные характеристики,
состав, источники и таблицы кривых. Ноль и «Нет» отличаются от отсутствующих
значений «—». Отметка неполноты указывает отсутствие основных данных/цены,
а не заключение о монтажной пригодности.

## Файлы

Справа расположены чертёж (для насосов), CAD-модель, папка и копирование пути.
Зелёная галочка скачивает проверенный файл. Серый крестик означает отсутствие,
плюс открывает загрузку. Многоточие означает, что проверка ещё не завершена.
Сбой хранилища не выдаётся за отсутствие файла. Фильтр наличия проверяет всю
выборку порциями и показывает прогресс; список уточняется до завершения проверки.

Наличие CAD учитывает не только основной `manifest.json` и загруженные файлы,
но и точные привязки к ID из реестров 3D-сборки: затворы и обратные клапаны,
переходы, компенсаторы, прокладки, КИП, кронштейны, баки и их краны. Привязки
собраны в `app/equipment-cad-sources.ts`. Проверяется доступность исходного
STEP/SLDPRT и других CAD-форматов; при отсутствии файла в Equipment проверяется
опубликованный исходник с тем же хешем. Из нескольких зарегистрированных
вариантов используется первый доступный. В раскрытой строке перечислены
зарегистрированные исходники, а подсказка файла сохраняет примечания к геометрии
серии и исполнению. Непривязанные модели из библиотеки не назначаются по одному
сходству названия; наличие STL-превью не заменяет исходный CAD.

Фланцы, воротники, прокладки и метизы также используют реестры исходников
экспорта SolidWorks. Болт и шпилька сопоставляются по стандарту, диаметру и
точной длине; гайка и шайба — по стандарту и диаметру. Название подтверждённой
конфигурации SLDPRT указано в подсказке и раскрытой строке; её нужно выбрать
в SolidWorks после скачивания. Если толщина исходника отличается от каталога,
подсказка показывает оба значения. Реестр штампованных фланцев имеет приоритет
над прежними плоскими моделями. Дополнительные проверенные файловые привязки
хранятся в `data/equipment-cad-bindings.json` с контролем имени и производителя.
Крестик означает отсутствие доступного файла, связанного именно с этой позицией.
Результат полной проверки приведён в [отчёте от 06.11.2026](equipment-cad-audit-2026-11-06.md).

Исходные модели: SLDPRT, SLDASM, STEP/STP, IGES/IGS, Parasolid X_T/X_B,
до 100 МБ. Сборку с зависимостями следует сохранить **Pack and Go → ZIP**:
архив должен содержать SLDASM и детали, без шифрования, ZIP64 и внешних путей.
Архив хранится и скачивается целиком, не распаковывается сервером. Проверка
пакета не подтверждает полноту внутренних ссылок SOLIDWORKS. GLB/STL/OBJ
предпросмотра не считаются исходной CAD-моделью. Чертежи используют форматы
существующего загрузчика насосов, до 30 МБ.

Связи хранятся в D1 `equipment_files` по стабильному ключу категории/позиции
и назначению. Метаданные и байты используют существующие `manual_pump_files`
и `PUMP_FILES`. Миграция `0014_equipment_files.sql` добавляет только таблицу
связей; API также создаёт её, если отсутствует. Загрузка из этого раздела сразу
связывает файл с позицией, отдельного сохранения карточки не требуется.

## Локальная интеграция

`preview-full.mjs` и `preview-beta.mjs` подключают внутренний
`EQUIPMENT_ASSETS`: читают существующие привязки `manifest.json`, исходники
в `Equipment`, чертежи в `dist/client` и опубликованные CAD в `sources`
постоянной библиотеки. `EQUIPMENT_ROOT` переопределяет корень Equipment;
по умолчанию это соседняя с frontend папка. Загруженные файлы остаются
в постоянном `PUMP_FILES_DIR`, отдельно от сборки.

Кнопка папки открывает Проводник с выделенным файлом только на Windows
и при обращении к localhost/127.0.0.1. Публичный origin beta отключает её.
Браузер передаёт только ключ позиции: реальный путь определяется сервером,
проверяется после разрешения ссылок и должен оставаться внутри разрешённого
каталога. Обработчик не имеет отдельного публичного HTTP-порта.

При облачном запуске без локальной интеграции папка недоступна, доступный
путь можно скопировать. Подключение `PUMP_FILES` требуется для загрузки;
dev без этого binding отображает ошибку подключения хранилища. Исходники CAD,
отсутствующие на сервере, не отмечаются как доступные по одному имени файла.

## Проверки

`tests/equipment-admin.test.mjs` проверяет полноту категорий поставляемого
каталога, неактивный импорт D1, нулевые/логические характеристики, доступ всех
ролей, загрузку, скачивание, восстановление после перезапуска хранилища,
удалённые файлы, ZIP-пакеты и разрешённые пути Проводника. Запуск Проводника
в автоматических тестах заменён проверкой переданного пути.
