# Патрубки горизонтальных консольных насосов

Реестр `data/end-suction-ports.json` подключён к общему пространственному резолверу и подготовленным CAD-моделям. Проверено 1248 исполнений каталога: DN и типы соединений заполнены у всех, обе пространственные точки — у 1247. Единственный пропуск: Aquastrong EEZ65-50-200/214-2NZ. У него DN65/DN50, но заводской генератор файлов не содержит размерного рисунка (`Drawing is missing`, результат `a32a58b44d3ba5200ddce94362672fc2`). Координаты соседних исполнений не используются.

233 исполнения NIS используют проверенную систему координат нормализованного STEP и измеренную напорную плоскость из `Equipment/Pumps/3D_Normalized/normalization-index.json`. Связь требует совпадения исполнения, мощности, частоты, хеша STEP, габаритов и существующих точек. Явно заданные вручную роли и конфликтующие координаты не заменяются.

Остальные схемы получены из размерных таблиц или привязанных заводских чертежей. В `data/end-suction-port-reviews.json` сохранены прочитанные размеры 437 исполнений EEZ, EST и NIS G, идентификаторы чертежей и SHA-256. Исходные размеры остальных серий проверяются через подпись `sourceValues`. Начало — центр всасывающего фланца, X к двигателю, Z вверх; внешние нормали входа −X и выхода +Z.

Формулы различаются: EST, XST и NBS задают прямую высоту выхода над входом; EEZ, NIS G, NBW и MBL используют разность высот. У NBV высота входа включает заводскую раму H1. Для крупных MBL 2026 используется H, для остальных — H2. Неизвестные габариты сохраняются пустыми. Две противоречивые строки NBS используют прямой размер h2 без назначения общей высоты.

Воспроизведение из текущего локального каталога, без изменения его SQLite:

```
node scripts/prepare-end-suction-ports.mjs
node scripts/audit-end-suction-ports.mjs
node --test tests/end-suction-ports.test.mjs tests/pump-spatial.test.mjs tests/prepared-pump-cad.test.mjs
```

Оба скрипта также принимают `--snapshot=путь.json` к ресурсам с `pump_catalog_v2`. Генератор проверяет хеши источников, аудит вызывает тот же резолвер, что и сцена, и сохраняет `outputs/end-suction-ports/report.html` и `audit.json`. Хеш реестра входит в отпечаток сборки: сохранённые сцены обновляют патрубки при штатном пересчёте, сохраняя ручное размещение.
