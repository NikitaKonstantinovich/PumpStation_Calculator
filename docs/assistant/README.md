# База знаний AI-ассистента Pump Station

Подготовлено **30.10.2026** по текущим локальным исходникам приложения. База содержит **16 статей** для помощи пользователю: от первого подбора до разбора незавершённой спецификации. Чат AI-assistant подключён к Responses API: поиск выполняется локально на сервере, а найденные фрагменты передаются вместе с вопросом. Отдельный Vector Store не используется.

Срез включает незакоммиченные изменения. Он описывает локальный код, а не автоматически текущую опубликованную или запущенную сборку. Источники и решения по расхождениям указаны в [заметках проверки](review-notes.md).

## Что включено

У каждой статьи есть устойчивый ID, название, тема, допустимые профили и роли, ссылки на исходные документы и код. Для проверенного среза сохранены SHA-256 источников, статей и управляющих файлов в [source-lock.json](source-lock.json). Текст нормализуется в UTF-8 без BOM с переводами строк LF, чтобы переключение CRLF/LF в Git не считалось изменением расчётных правил.

Исторические аудиты, задания, планы и материалы отдельного reference-calculator-nu не индексируются. В корпус не входят пользователи, рабочие проекты, D1, ключи, env-файлы, резервные копии, полные каталоги и CAD.

Чат получает выбранные сведения о моделях, базовых правилах и текущем собственном проекте через серверные инструменты чтения. Они проверяют сессию, владельца и профиль, затем передают в API ограниченный результат поиска. Документация объясняет правила и ограничения; она не заменяет живые данные.

## Сборка пакета

Из корня frontend:

```powershell
node scripts/build-assistant-knowledge.mjs
node scripts/build-assistant-knowledge.mjs --check
node --test tests/assistant-knowledge.test.mjs
```

Результат создаётся в игнорируемой Git папке `work/assistant-knowledge/`:

| Файл | Назначение |
| --- | --- |
| `files/KB-001.md` … `files/KB-016.md` | Только подготовленные статьи для загрузки в поиск |
| `manifest.json` | ID, имя файла, заголовок, аудитория, профиль, хеш, источники и путь для цитирования |
| `validation.json` | Число документов, источников, контрольных вопросов и границы выполненной проверки |

Сборщик не делает сетевых запросов, не читает локальный API-ключ и не включает помощника. Он не добавлен в обычный prebuild: сборка приложения не должна загружать документы или тратить API-кредиты.

Сборка проверяет список статей, локальные ссылки, отсутствие похожих на ключи значений, аудиторию, контрольные вопросы и совпадение источников с принятым срезом. При лишнем старом файле в выходном наборе она останавливается, чтобы его случайно не загрузили вместе с актуальными материалами.

## Обновление после изменения приложения

1. Запустите сборщик. Изменение любого учтённого источника требует пересмотра соответствующих статей; связи перечислены в manifest.json и разделах «Источники».
2. Сверьте новое поведение с кодом. Обновите текст, реестр, дату проверки и контрольные вопросы по необходимости.
3. После смысловой проверки явно примите новый срез и пересоберите пакет:

```powershell
node scripts/build-assistant-knowledge.mjs --accept-reviewed-sources
node scripts/build-assistant-knowledge.mjs
node scripts/build-assistant-knowledge.mjs --check
node --test tests/assistant-knowledge.test.mjs
```

Команда принятия фиксирует хеши, но не проверяет смысл изменений вместо редактора. Изменение файла источника может касаться другой функции; тогда достаточно убедиться, что статья остаётся верной.

Для удаления статьи сначала пересмотрите соответствующие вопросы и реестр, затем вручную проверьте оставшийся выходной файл. Сборщик не удаляет файлы автоматически.

## Подключение к чату

Реализация и настройки описаны в [AI-assistant](../ai-assistant.md). В prebuild добавлена сборка серверного корпуса `build-assistant-runtime.mjs`, которая проверяет принятый срез и не обращается к API.

[Инструкции ассистенту](assistant-instructions.md) хранятся отдельно от поискового корпуса и передаются как серверные инструкции. Роль и профиль ограничивают набор документов **до** передачи найденного текста модели; одних указаний в промпте недостаточно.

Серверный корпус собирается из подготовленных статей пакета. Текущий поиск не загружает файлы в OpenAI: в каждом запросе отправляются только выбранные фрагменты. Источники ответа проверяются по KB-ID и открываются в Центре помощи: `/?view=help&tab=documentation&doc=KB-001`. Поле `citation.url` содержит относительную ссылку на соответствующий документ.

## Проверка ответов

[32 контрольных сценария](evaluation-cases.json) содержат вопрос, профиль, роль, ожидаемые статьи, обязательные положения и недопустимые утверждения. Среди них: отсутствие результатов подбора, давление, стоимость черновика, границы массы рамы, обновление 3D, версии тарифов, неизвестная цена, отсутствие контекста проекта и попытка получить секрет из текста документа.

Сборщик проверяет структуру сценариев и доступность ожидаемых источников. Реальная точность поиска, ссылки ответов и поведение модели проверяются после подключения API; результаты ручных запросов не являются проверкой всех сценариев.
