# AI-assistant — чат с Pump-иком

AI-assistant — инструмент рабочего пространства в full и beta для base, plus, pro и admin. Откройте «Добавить инструмент» и выберите «AI-assistant» в заголовке окна; в сетке выберите его в пустой ячейке. Окно можно перемещать, менять его размер, сворачивать и открывать в отдельной вкладке.

## Начало диалога

Pump-ик встречает сообщением: «Привет, я - Pump-ик! Есть вопросы по работе приложения? Готов ответить ;)». Его аватар — небольшой синий насос. Задайте вопрос о работе программы или нажмите один из предложенных вопросов.

Enter отправляет сообщение, Shift+Enter добавляет строку. Во время ожидания можно остановить ответ; при ошибке — повторить вопрос. Кнопка «Новый диалог» очищает историю текущей вкладки. Остановка не гарантирует отмену уже начатой обработки у поставщика API.

## Ответы по документации

Сервер ищет фрагменты проверенной базы знаний, учитывая роль из сессии и профиль сборки, затем передаёт вопрос, ограниченную историю и найденные фрагменты в OpenAI Responses API. По вопросам о конкретных числах модель вызывает разрешённые серверные функции чтения. Ссылки на статьи ведут в Центр помощи; источники из базы отмечены названием и временем чтения. Pump-ик не изменяет данные приложения.

Доступны опубликованные базовые значения и версии, закреплённые за проектом: расстояния, скорости, курсы и скидки, сварка, окраска и предпочтения. Насосы ищутся в действующем каталоге; межосевое расстояние определяет функция приложения `spacingForPump`, а не арифметика модели. Отдельно читаются действующий импорт комплектующих D1, сохранённые вставки и, в full, сохранённые коллекторы. Цены сохранённых изделий являются снимком и могут устареть.

В full инструмент получает ID открытого проекта и читает только его последнюю сохранённую версию с проверкой `id AND user_id`. В контекст входят технические поля Q/H, выбранные насосы, настройки, DN, межосевые расстояния и версии правил. Название проекта, произвольные заметки, 3D-сцена, полный состав спецификации, сведения об авторах и учётные данные не передаются. В beta используются параметры текущей вкладки, явно отмеченные как пользовательский ввод; значения правил разрешаются на сервере по ID публикаций. Нельзя заменить закреплённые значения последней публикацией без указания этого различия. При ошибке чтения помощник сообщает об отсутствии данных.

Владелец разрешил передавать в OpenAI API необходимые результаты такого чтения для ответов Pump-ика. Отправляется выбранная страница поиска, а не дамп базы. Инструменты не принимают SQL, адрес внешнего сервера, ID другого пользователя или команды записи. Чтение опубликованных правил доступно всем уровням, черновики административных настроек не выдаются. Каждый новый вопрос проверяет данные заново.

Чат помогает пользоваться приложением. Он не заменяет расчётный код, актуальную карточку оборудования или инженерную проверку. При отсутствии сведений в документации помощник должен уточнить вопрос или сообщить об ограничении.

## История и доступ

История отделена от файлов проекта. Последние 30 сообщений хранятся в sessionStorage отдельно для пользователя и текущего проекта (в beta — для текущего рабочего пространства) и сохраняются при обновлении страницы или сворачивании инструмента в этой вкладке. Между устройствами история не синхронизируется. Для одного аккаунта отправляется не более одного запроса одновременно, 6 вопросов в минуту и 60 в сутки UTC. Эти счётчики общие для сессий и хранятся в D1.

В API передаются до 12 последних сообщений, не более 20000 символов истории; вопрос ограничен 4000 символами. Один вопрос допускает до 6 обращений к источникам и 4 запросов к модели, с общим ожиданием до 90 секунд. Ответ каждого запроса к модели ограничен 1600 токенами. Дополнительные обращения для работы с данными увеличивают расход API. Запрос использует `store: false`; это не заявление об отсутствии технического хранения данных у поставщика.

## Настройка сервера

Локальный `preview-full.mjs` читает игнорируемый `.env.ai.local`. Требуются OPENAI_API_KEY, OPENAI_MODEL (по умолчанию gpt-6-luna) и AI_ASSISTANT_ENABLED=true. В опубликованном Worker задайте те же значения через серверные bindings/secrets. Ключ не передаётся браузеру и не встраивается в сборку. При отключённом помощнике видны приветствие и контакт поддержки, отправка недоступна.

Локальный preview использует внутренний service binding AI_PROVIDER и HTTP-клиент Node, как `check-ai-connection.mjs`. Он принимает только POST к фиксированному endpoint Responses API. В опубликованном Worker без этого binding запрос выполняется встроенным fetch; доступность API в среде размещения проверяется отдельно.

Поиск выполняется на сервере по `app/assistant-knowledge.json`; отдельный Vector Store не требуется. `scripts/build-assistant-runtime.mjs` проверяет принятый срез источников и собирает только статьи из реестра с серверными инструкциями. Он включён в prebuild и не выполняет платных запросов. После изменения инструкций или исходников пересмотрите затронутые статьи и обновите source-lock по процедуре в `docs/assistant/README.md`.

При первом запросе сервер идемпотентно создаёт таблицу `ai_assistant_usage` для счётчиков и блокировки параллельных запросов. В ней нет текстов диалогов. API проверяет авторизацию, источник запроса, размер тела и допустимые роли сообщений до вызова модели. Внешние URL из ответа модели не становятся кликабельными; ссылки на статьи сверяются с найденными источниками.

Подключение использует [Responses API](https://developers.openai.com/api/docs/guides/text), [управление историей](https://developers.openai.com/api/docs/guides/conversation-state) и [function calling](https://developers.openai.com/api/docs/guides/function-calling). Сервер валидирует аргументы независимо от strict JSON Schema, ограничивает число вызовов, размер результата и допустимые источники. Проверки: `tests/assistant-data.test.mjs`, `tests/ai-assistant.test.mjs`, `tests/assistant-chat-store.test.mjs`.
