# Ручная сборка инструмента «Подбор насосов»

Работайте в полном профиле как admin: главное меню → «Нодовый редактор». Здесь один общий граф продукта. Библиотека содержит необходимые операции; пользовательский подбор не создаётся автоматически. Учебный граф в tests/fixtures/pump-product.mjs используется только изолированными проверками.

## 1. Каркас и внешний контракт

1. Нажмите «＋ Инструмент», введите «Подбор насосов». Карточка появится рядом с «Настройками проекта» на общем полотне. Её ID сохраняется при переименовании.
2. Нажмите «Раскрыть Instrument». Уже созданы «Данные инструмента», «Собственные значения инструмента», «Форма инструмента», «Сохранить значения», «Расчётный результат» и «Результат инструмента». Поля и команда сохранения связаны с собственным состоянием этого экземпляра.
3. «Расчётный результат» пока создаёт пустой объект. Удалите эту пустую ноду вместе с её связью к выходной границе. Форму и команду сохранения оставьте.
4. Вернитесь к корневой карточке через хлебные крошки. Нажмите «Входы и выходы инструмента».
5. Через «+ Атрибут» добавьте вход: стабильный ключ `settings`, имя «Настройки проекта», тип «Объект», направление «Вход», инженерный смысл `record`, единица пустая. Это вход действующего результата настроек.
6. У существующего выходного атрибута `value` оставьте тип «Объект» и направление «Выход», задайте имя «Выбранное исполнение» и инженерный смысл `pumpCatalogItem`. Не меняйте устойчивый ключ.
7. Нажмите «Применить определение». Внутренние границы обновятся вместе с контрактом. Системные `context` и `ui` сохраняйте: первый получает доверенный контекст экземпляра, второй передаёт форму.
8. На общем полотне соедините выход `value` «Настроек проекта» со входом `settings` «Подбора насосов». Скрытый выход доступен через ПКМ → «Передать атрибут…». Соединяется расчётный результат, а не сохранённый JSON другого инструмента.

## 2. Ноды внутри подбора

Раскройте «Подбор насосов». Через «＋ Библиотека» добавьте:

| Название в библиотеке | Назначение |
| --- | --- |
| Новый каталог насосов | Зарегистрированный источник `pump_catalog_v2` |
| Условия подбора из настроек | Активный контур, Q, H, число рабочих насосов, среда |
| Фильтрация каталога насосов | Пригодность, среда, Q/H-кривая и фильтры |
| Проверка напора по характеристике | Проверка при Q/n и минимального запаса |
| Рабочая точка кандидатов | Существующая математика рабочей точки и цены |
| Сортировка результатов подбора | Порядок и ограничение строк |
| Параметр выбранного насоса | Подтверждённый пользователем выбор |
| Таблица кандидатов насосов | Просмотр и выбор исполнения |
| Проверка выбранного исполнения | Проверка подтверждения для текущих условий |
| Карточка выбранного насоса | Результат и замечания о полноте данных |

У «Параметра выбранного насоса» привязка к существующему источнику состояния создаётся автоматически при добавлении из библиотеки. Убедитесь в наличии связей «Собственные значения инструмента»: `value → values`, `role → role`. Этот параметр предназначен для таблицы; отдельное текстовое поле подтверждения не нужно.

У «Условий подбора из настроек» выберите основной или второй контур. Статический напор задаётся отдельно по условиям расчёта. Входной напор станции автоматически статическим напором не считается. Число резервных насосов не используется как число работающих.

## 3. Таблица соединений

В таблице указаны устойчивые ключи портов. Их русские названия и контракты доступны в свойствах. Перетаскивайте выход к входу; скрытые атрибуты выбирайте через ПКМ.

| Откуда | Выход | Куда | Вход |
| --- | --- | --- | --- |
| Данные инструмента | `settings` | Условия подбора из настроек | `settings` |
| Новый каталог насосов | `value` | Фильтрация каталога насосов | `catalog` |
| Условия подбора из настроек | `value` | Фильтрация каталога насосов | `request` |
| Фильтрация каталога насосов | `value` | Проверка напора по характеристике | `candidates` |
| Проверка напора по характеристике | `value` | Рабочая точка кандидатов | `candidates` |
| Данные инструмента | `settings` | Рабочая точка кандидатов | `pricing` |
| Рабочая точка кандидатов | `value` | Сортировка результатов подбора | `candidates` |
| Сортировка результатов подбора | `value` | Таблица кандидатов насосов | `candidates` |
| Параметр выбранного насоса | `binding` | Таблица кандидатов насосов | `binding` |
| Сортировка результатов подбора | `value` | Проверка выбранного исполнения | `candidates` |
| Параметр выбранного насоса | `binding` | Проверка выбранного исполнения | `binding` |
| Проверка выбранного исполнения | `value` | Карточка выбранного насоса | `item` |
| Проверка выбранного исполнения | `selection` | Карточка выбранного насоса | `selection` |
| Таблица кандидатов насосов | `value` | Форма инструмента | `child0` |
| Карточка выбранного насоса | `value` | Форма инструмента | `child1` |
| Проверка выбранного исполнения | `value` | Результат инструмента | `value` |

Каркас уже соединяет `Форма.value → Результат.ui` и `Сохранить значения.value → Форма.command`. Сохраните эти связи.

Настройте колонки таблицы через «Колонки»: основные, технические, цена и отклонения либо свой список ключей. При выборе собственного списка используются известные ключи, например `model,manufacturer,series,power,headReservePercent,purchasePriceRub`. Неизвестные значения отображаются как неизвестные.

## 4. Динамические фильтры

Для производителя создайте «Новый параметр»: ключ `manufacturer`, тип `string`, инженерный смысл `text`, единица пустая, необязательный. Источник значения — «Ввод пользователя».

Помощник создаст обычное поле. Снимите у него «Показывать в форме», сохранив параметр. Добавьте «Варианты фильтра из каталога» и «Динамический список выбора»:

| Откуда | Выход | Куда | Вход |
| --- | --- | --- | --- |
| Новый каталог насосов | `value` | Варианты фильтра из каталога | `catalog` |
| Варианты фильтра из каталога | `options` | Динамический список выбора | `options` |
| Параметр manufacturer | `binding` | Динамический список выбора | `binding` |
| Параметр manufacturer | `value` | Фильтрация каталога насосов | `manufacturer` |
| Динамический список выбора | `value` | Форма инструмента | свободный `childN` |

У ноды вариантов выберите атрибут «Производитель», у списка подпись «Производитель». Пустой вариант «Все» снимает ограничение. Для серии и типа повторите схему с отдельными параметрами и соответствующими атрибутами. Новые значения появятся из обновлённого снимка каталога.

## 5. Проверка, публикация и сохранение

1. Выберите «Настройки проекта» и заполните тестовые значения. Эти значения сохраняются отдельно от тестовых значений подбора при переключении инструментов.
2. Выберите «Подбор насосов». В панели каталога проверьте загрузку и ID снимка. Недоступный источник, пустой каталог и незаполненные условия имеют разные сообщения.
3. Проверьте таблицу. Подбор сам не подтверждает первую строку. Нажмите строку/переключатель нужного исполнения; должна появиться карточка гидравлического выбора.
4. Измените расход или напор настроек. Старый выбор должен стать устаревшим. Его ID сохраняется, расчётный выход выбранного исполнения становится пустым до повторного подтверждения. Можно очистить выбор или подтвердить подходящую строку заново.
5. Нажмите «▷ Проверить», сохраните черновик и опубликуйте.
6. В Workspace 2 нажмите «Применить актуальную версию продукта», просмотрите отчёт миграции и сохраните значения. Старый проект не меняется только от публикации.
7. Перезагрузите страницу: должны сохраниться единая версия продукта, собственные параметры инструментов, выбранное исполнение и ID снимка каталога.

Подписи происхождения скрываются через «Свойства формы → Показывать источник значения». Индивидуальные настройки сохраняются; инспектор продолжает показывать источник.

## Источник и воспроизводимость

Логический источник `pump_catalog_v2` настроен сервером. Локальный полный профиль читает `database/catalog-v2/pumps.sqlite` только для чтения; путь при необходимости задаётся серверной переменной `NODE_PUMP_CATALOG_PATH`. Узлы не принимают произвольные пути, SQL или сетевые адреса.

Полученный снимок нормализуется, получает ID по содержимому и сохраняется неизменяемыми ограниченными по размеру блоками в D1. Проект содержит ссылки на версии и подтверждение выбора, а не полную копию каталога. Закреплённый снимок читается независимо от текущего файла. «Обновить снимок каталога» в редакторе и явное применение актуальной версии продукта в Workspace 2 получают новые данные и требуют повторной проверки старого выбора.

Сохраняются modelId, variantId, curveSetId, частота, происхождение, цены и неизвестные значения. Полнота гидравлических данных проверяется отдельно от данных исполнения, монтажа и CAD. Подтверждённая гидравлическая точка не подтверждает неизвестный PN, точную геометрию или готовность 3D-компоновки.

Старое рабочее пространство продолжает использовать свой каталог и алгоритм. Удалённые инструменты доступны через сохранённые состояния и историю; производственные пользовательские графы не заменяются учебным примером.
