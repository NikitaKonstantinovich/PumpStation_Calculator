# Воротники: SLDPRT → STEP и проверка вставок, 25.10.2026

Работа выполнена в основной ветке `main`. Перед изменениями сохранены
пользовательские файлы и согласованная копия SQLite в
`work/backups/before-collar-step-20261025T190325Z.*`. Исходные SLDPRT не изменены.

## Конвертация и контроль геометрии

Найдены 20 разных SLDPRT в двух папках `Equipment/Piping/3D/Воротники` и
`Equipment/Piping/3D/Элементы трубопроводов/Воротники`. Все 20 перенесены в STEP:
`Equipment/Piping/3D/Воротники STEP`. Имена файлов содержат префикс SHA-256
исходника; полные соответствия, контрольные суммы, измерения и профили находятся
в `data/collar-cad-models.json`.

Использован локальный открытый [cadmpeg 0.6.6](https://github.com/cadmpeg/cadmpeg/releases/tag/v0.6.6)
(Apache-2.0) для чтения аналитической геометрии Parasolid из SolidWorks.
Файлы не отправлялись внешнему сервису. Архив конвертера проверен по SHA-256
официального выпуска. Прямой STEP-экспорт этого выпуска неправильно выбирает
участки некоторых тороидальных поверхностей: у DN100 появляется выход на −6 мм
и объём около 94 560 мм³ вместо 37 988,529 мм³. Такой результат не использован.

`scripts/convert-collar-cadir.py` переносит точный меридиональный профиль из
аналитических плоскостей, цилиндров, торов и вершин граничных рёбер исходного
B-Rep в OpenCascade. Принимаются только соосные тела вращения с замкнутым
профилем; неизвестная геометрия и разрывы запрещены. Размеры не снимаются с STL.
Кэш отображения SolidWorks служит независимой проверкой выбора участков
скруглений (порог 0,3 мм относится только к грубой экранной сетке, не к точности
измерения модели). У зеркального DN65 нет такого кэша: его точные профили
совпали с отдельно проверенной моделью DN65; ссылка на подтверждающий отчёт
записана в данных.

Повторное чтение всех STEP и проверка B-Rep прошли успешно. Сохранены 23 тела:
17 файлов содержат одно тело, три — по два. Многотельные файлы не использованы
для автоматического назначения размеров каталогу. `scripts/measure-collar-step.py`
отдельно измеряет плоскости и цилиндры уже полученного STEP в миллиметрах.
Контроль положительного объёма выполнен для каждого тела.

Все 20 моделей подготовлены для ручной установки в 3D-редакторе. Общая локальная
библиотека теперь содержит 4193 готовые модели; прежние три ошибки другой
геометрии остались без изменений. Точки подключения автоматически не назначались.

## Несовпадения, которые не заменены догадками

- В файле DN80 фактический наружный диаметр 85 мм, в каталоге — 88,9 мм.
- Модели DN150 имеют наружный диаметр 154 мм, каталог — 168,3 мм.
- Один DN125 имеет 133 × 3 мм вместо каталожных 139,7 × 3 мм.
- Один DN65 имеет 70 × 2 мм; у модели 76,1 × 2 мм длина 25 мм, тогда как
  ранее пользователь подтвердил 23 мм. Подтверждённые размеры не перезаписаны.
- Два DN50 со стенкой 2 мм имеют длины 12 и 23 мм. Существующая длина 23 мм
  сохранена; одинаковый DN не делает эти исполнения одинаковыми.
- Моделей нужной стенки 3 мм для многих PN16, DN15/20 и больших DN нет.

После обновления полная длина известна у 15 из 40 воротников. Остались:

- PN10: DN80, 150, 250, 300, 350, 400, 500, 600, 700, 800.
- PN16: DN15, 20, 32, 40, 50, 65, 200, 250, 300, 350, 400, 500, 600, 700, 800.

Остальные ограничения из проверки переходов сохраняются: 217 неизвестных длин
переходов, 462 неподтверждённых профиля/шейки, свободные фланцы PN16, конфликт
материала фланцев PN25, исполнение/PN сгонов, резьбовые концы и отдельные размеры
крепежа. Модели воротников этих вопросов не разрешают.

## Результат расчёта и проверки

Повторно рассчитана активная база: DN15–800, оба материала, эксцентрические
переходы включены, всего 576 вариантов в каждом сценарии.

| Сценарий | Полных до | Полных после |
| --- | ---: | ---: |
| Без сгона, посадка воротника «по источнику» | 20 | 20 |
| Без сгона, явно заданная глубина посадки воротника 0 мм | 66 | **81** |
| Со сгоном, посадка «по источнику» | 0 | 0 |

Нулевая глубина использовалась только как явный ввод при проверке; настройка
пользователя не менялась. Добавились 15 полных вставок AISI304 PN10: три прямые
(DN100/125/200) и 12 с концентрическими/эксцентрическими переходами.
DN25 PN16 получил длину, но другие ограничения его расчёта остались.

Пример по действующим тарифам: DN100–DN100 AISI304 PN10, глубина посадки 0 мм:
труба 120 мм + два воротника по 16 мм = **152 мм**. Состав 552,0831 ₽,
сварка 7181,6808 ₽, итог **7733,76 ₽**. По существующей методике коллектора
два соединения с коэффициентом 2 дают 1436,336 мм шва. Свободные фланцы не
добавлены к длине, составу, цене или числу швов.

Проверены отсутствие дублей идентичности, положительные размеры/цены готовых
строк, отсутствие итоговой цены у неполных. Пройдены **65 Node-тестов** расчёта,
каталога, прав admin, сохранения/обновления, устаревания и отката; **3 Python-теста**
точной геометрии и отказа при повреждённых данных; TypeScript, ESLint изменённых
JS/TS-файлов и полная сборка. HTTP: главная 200, профиль `full`, защищённые API
и библиотека без авторизации — 401.

Основная сборка запущена на `http://localhost:3000/`, использует ту же
сохранённую базу. Процесс сборки сохраняет прежнюю метку версии `beta 0.1`,
но профиль приложения — **full**, не beta.

## Воспроизведение

1. `cadmpeg dump <исходный.SLDPRT> -o <модель.cadir.json>`.
2. `python scripts/convert-collar-cadir.py <модель.cadir.json> <модель.step> --report <проверка.json>`.
   Для зеркального файла без кэша: `--verified-profile-report <отчёт-проверенного-DN65.json>`;
   точный профиль обязан совпасть, иначе экспорт запрещён.
3. `python scripts/measure-collar-step.py <модель.step>` — независимое измерение.
   Все 20 файлов и исходники: `python scripts/measure-collar-step.py --manifest data/collar-cad-models.json`.
4. `node --experimental-strip-types scripts/import-collar-dimensions.mjs --database <база.sqlite>` —
   проверка SHA-256 исходников/STEP, резервная копия, импорт и проверка целостности.
5. `node --test tests/collar-dimensions.test.mjs tests/component-insert-calculations.test.mjs tests/component-insertions-server.test.mjs tests/insert-shared-fasteners.test.mjs`.
6. `python -m unittest discover -s tests -p test_collar_step.py -v` — требуется OCP.
