# Сохранение компоновки в SOLIDWORKS и eDrawings

1. Завершите компоновку установки в браузере.
2. Выберите **Расчёт → Собрать в SOLIDWORKS**. Исполнитель сохранит отдельный снимок проекта и проверит собранные детали.
3. В инструменте **3D-модель → Предупреждения SOLIDWORKS** посмотрите итог и пропущенные экземпляры. Нажатие на имя переводит редактор к соответствующему компоненту. Для каждого пропуска доступны причина, способ исправления, ID экземпляра, узел и известная позиция спецификации.
4. После готовности используйте **Расчёт → Сохранить 3D**. **Проект SOLIDWORKS** скачивает ZIP со сборкой, зависимостями и `export/report.json`. **Сборка eDrawings** скачивает EASM для установленного просмотрщика. **Автономный eDrawings** скачивает `pumpstation.exe` для Windows x64: модель и просмотрщик внутри, отдельная установка не нужна. Оба формата eDrawings доступны и для неполной сборки; отчёт скачивается отдельной ссылкой.

Полная и неполная сборки разрешают сохранение без дополнительного подтверждения. Предупреждения считаются по физическим экземплярам. При отсутствии всех деталей или технической ошибке проверки сборки сохранение блокируется. Все попытки хранятся в отдельных каталогах.

Доступ соответствует 3D-редактору: pro/admin при включённом расчёте геометрии.
В beta функция закрыта. Пока серверный исполнитель не настроен, интерфейс
сообщает, что сервис сборки не подключён.

## Источник компоновки

Единственный источник положений — текущий `station-model.editor.assembly`.
При экспорте не выполняются автокомпоновка, обновление состава, следование
патрубкам, центрирование или масштабирование. Несохранённые ручные правки,
уже переданные редактором в состояние проекта, входят в снимок.

Передаются физические экземпляры, их ID, ID оборудования, выбранные исходные
CAD-модели по SHA-256, параметры собственных деталей и полные преобразования.
Вложенная деталь учитывает базы компонента, детали и исходной модели ровно один
раз. Система браузера — правая, Z вверх, размеры в мм, углы Euler XYZ.
В API SOLIDWORKS передаются строки осей матрицы и перенос в метрах, масштаб 1.
Скрытые элементы остаются в составе; скрытие используется только для видимости.
Информационные строки крепежа не создают повторные физические экземпляры.

SOLIDWORKS фиксирует каждую деталь в полученном положении. Свободное
редактирование положений возможно после снятия фиксации пользователем;
сопряжения на этом этапе не создаются. Перестроение не должно менять положение.
Проверяются число экземпляров и фактические матрицы после перестроения:
допуск переноса 0,0001 мм, элементов вращения 1e-8.
При сборке исполнитель создаёт автономный каталог Pack and Go, закрывает исходные документы и открывает сборку из этого каталога. Он сверяет экземпляры и матрицы и проверяет пути зависимостей. По команде сохранения сервис упаковывает этот каталог в ZIP или открывает сохранённую сборку для экспорта EASM. Готовый формат выдаётся из кэша задания. Ошибку экспорта формата можно повторить без пересборки.

Для EXE используется проверенный EASM того же снимка. Если формат ещё не запрошен, исполнитель сначала создаёт EASM из готовой сборки. Затем eDrawings x64 открывает его, сверяет дерево и записывает автономный файл штатным [методом Save](https://help.solidworks.com/2023/English/api/emodelapi/eDrawings.Interop.EModelViewControl~eDrawings.Interop.EModelViewControl.IEModelViewControl~Save.html). EXE становится доступен после события завершения записи, проверки заголовка Windows x64 и переименования временного файла. Ошибка выпуска EXE не лишает пользователя готового EASM. Это [автономный формат eDrawings](https://help.solidworks.com/2023/english/eDrawings/t_Saving_Files_as_Executable_Files.htm), а не установщик калькулятора.

## Актуальность

SHA-256 снимка рассчитывается по составу, идентификаторам и геометрии экземпляров, параметрам и преобразованиям. Перемещения, повороты, замены моделей и изменения размеров требуют новой сборки, в том числе когда правка внесена во время обработки. Камера, выделение, прозрачность и скрытие для просмотра сохраняют доступ к готовому результату. В файле остаётся видимость, зафиксированная при запуске задания. При проверке статуса и перед выдачей файлов сервис сверяет версии исходных CAD, использованных при подготовке. После добавления модели для ранее пропущенной позиции запустите новую сборку.

Статус, ID снимка, перечень пропусков и доступные форматы хранятся на сервере. После перезагрузки браузер сопоставляет результат с текущей компоновкой. Проекты, экспортированные старым исполнителем, можно скачать по существующей ссылке. Для нового меню им потребуется одна сборка.

## Геометрия и ограничения

В дереве SOLIDWORKS каждый физический экземпляр получает отдельную запись.
Имена документов в ZIP содержат наименование и типоразмер. Для изготовляемых
труб в имени указываются наружный диаметр, толщина стенки и известная длина.
При повторном открытии сборщик проверяет имена, положение, наличие твёрдых
тел, выбранную конфигурацию и назначенный цвет каждого экземпляра.

Исполнитель сверяет детали с `data/solidworks-parts.json`. Для DIN 933,
DIN 934, DIN 125 и шпилек сравниваются типоразмер и монтажная база. Для
фланцев проверяются позиция, размеры и сверловка. Воротники с проверенной
привязкой к STEP получают исходный SLDPRT. Если модели точного исполнения
нет, поддерживаемая собственная деталь выпускается по размерам снимка.
В `export/verification.json` у каждого включённого экземпляра указаны
источник, конфигурация, имя в дереве, файл и количество твёрдых тел.

Стальная обвязка окрашивается в красный, нержавеющая получает металлический
вид. Для арматуры учитывается исполнение спецификации. При подборе пожарного
контура в приоритете красное исполнение, хозяйственно-питьевого — синее.
При отсутствии нужного цвета допускается совместимая арматура другого цвета.

Браузерные STL не используются для конструкторского экспорта. Исполнитель
разрешает исходные STEP/STP/SLDPRT/SLDASM через серверные реестры и проверяет
SHA-256. Исходные файлы должны находиться в `Equipment` внутри корня библиотеки.
Выбор произвольного пути из браузера не разрешает доступ к другим файлам.

Для труб, колец, фланцев с отверстиями и выступом, воротников, крепежа и
коллекторов с седловыми патрубками создаются аналитические твёрдые тела OCP,
которые SOLIDWORKS импортирует и сохраняет в родном формате. История эскизов
и операций для импортированных тел не восстанавливается. Резьба этих деталей
имеет номинальную поверхность без винтового профиля; примечание входит в задание.

Условные габариты насосов, рам и прочего оборудования не превращаются в
конструкторские детали. Для них нужна реальная модель точного исполнения.
Для неподдерживаемой геометрии, отсутствующего или изменённого исходника, ошибки импорта или построения отдельного элемента исполнитель записывает пропуск в отчёт и продолжает сборку доступных деталей. В отчёте сохраняется каждый пропущенный экземпляр, даже если у нескольких одна модель.
Геометрические предположения коллекторов сохраняются в примечаниях.

Дополнительные проверенные модели можно зарегистрировать в JSON, путь к которому
задаётся только администратором через `CAD_EXPORT_LIBRARY`:

```json
{
  "models": [{
    "equipmentId": "frame-execution-id",
    "parameters": {
      "length": 1200, "width": 600, "height": 80,
      "diameter": 50, "routeOffset": 0
    },
    "source": "Equipment/Frames/approved-frame.SLDPRT",
    "sourceHash": "SHA256_ИСХОДНОГО_ФАЙЛА"
  }]
}
```

Все параметры должны точно совпасть со снимком. Масштабирование готовой рамы
до запрошенных габаритов не выполняется. Для параметрических исполнений рам
нужен отдельный проверенный генератор или подготовленная модель исполнения.

## Запуск Windows-исполнителя

Нужны выделенная свободная Windows-сессия с доступным лицензированным SOLIDWORKS,
.NET 9 x64, Python с зависимостями `services/model-converter/requirements.txt`,
библиотека моделей и шаблоны ASMDOT/PRTDOT используемой версии.
При размещении исполнителя в отдельной папке релиза параметр `--root`
(`CAD_EXPORT_ROOT` в профиле) должен указывать на корень установки с
`frontend/scripts/model_assets.py` и `Equipment`. Оттуда этап `prepare`
загружает реестр и проверяет контрольные суммы моделей. Проверка сохранения
готового EASM или EXE не запускает этот этап: после обновления исполнителя
проверьте также «Собрать в SOLIDWORKS» на новом задании.
Исполнитель отказывается работать, если SOLIDWORKS уже запущен в доступной сессии.
Не используйте сессию конструктора для автоматической очереди.

Из каталога `frontend`:

```powershell
dotnet build services/solidworks-export/runner/SolidWorksExport.csproj -c Release
```

Если библиотеки API находятся в другом каталоге, задайте
`-p:SolidWorksApiDir="C:\путь\к\SOLIDWORKS\api\redist"`.
Используйте Python существующего CAD-окружения. Задайте в его процессе
`CAD_EXPORT_TOKEN` — случайный серверный секрет длиной не менее 24 символов.

```powershell
python services/solidworks-export/server.py `
  --root E:\PumpStation_Calculator `
  --state E:\PumpStation_Calculator\work\cad-export-state `
  --runner services\solidworks-export\runner\bin\Release\net9.0-windows\SolidWorksExport.exe `
  --template "C:\ProgramData\SOLIDWORKS\SOLIDWORKS 2023\templates\gost-assy.asmdot" `
  --part-template "C:\ProgramData\SOLIDWORKS\SOLIDWORKS 2023\templates\gost-part.prtdot"
```

Команда слушает только `127.0.0.1:8767`. Для удалённого исполнителя нужен
закрытый канал HTTPS между сервером приложения и исполнителем. В браузер
адрес и секрет исполнителя не передаются.

На сервере приложения задайте `CAD_EXPORT_URL=http://127.0.0.1:8767` и тот же
`CAD_EXPORT_TOKEN`. Локальный `preview-full.mjs` передаёт эти переменные в Worker.
При запуске через `start-local.ps1` их можно добавить в личный `full.json`;
саму очередь запускают отдельно приведённой командой.

## Очередь и результат

Задания и входные снимки сохраняются на постоянном диске. Один процесс
исполняет их последовательно; каталог состояния защищён от второго процесса.
Для владельца проекта одновременно допускается одно активное задание.
Повтор одного requestId возвращает то же задание; другой снимок под тем же ID
отклоняется. Максимум 20 активных заданий в общей очереди, вход 16 МБ,
до 30000 физических деталей после раскрытия крепежа и собственных изделий.

API приложения связывает запрос с текущей учётной записью. Получить статус и
скачать результат может только владелец; сервис доступен по серверному секрету.
Скачивание идёт потоком через приложение без публичной ссылки на диск.

Закрытие окна или смена вкладки не останавливает принятое задание. При открытии
«Расчёт» приложение получает его актуальный статус. Перезапуск очереди помечает
прерванные задания ошибкой и требует явного повторного формирования.
Пока задание выполняется, кнопка показывает «Идёт сборка в SOLIDWORKS…».
Рядом отображаются фактические этапы: подготовка разных CAD-моделей,
размещение физических экземпляров (с количеством обработанных), перестроение,
упаковка зависимостей и проверка упакованной сборки. До окончания проверки
скачивание закрыто. После технической ошибки доступен повторный запуск.
После подготовки формата соответствующий пункт «Сохранить 3D» становится
прямой ссылкой на файл. Если браузер не начал автоматическую загрузку
после ожидания, этот пункт скачивает файл обычным нажатием без повторного экспорта.
При сборке лимит `--timeout` (по умолчанию 30 минут) отсчитывается от последнего
перехода на новый этап или увеличения номера обработанного элемента. Поэтому
большая установка может собираться дольше 30 минут. Повторная запись того же
значения, старый этап и опрос статуса из браузера отсчёт не продлевают.
Отдельный предельный срок `--max-runtime` — 4 часа на этап исполнителя.
Компоненты вставляются пакетами до 32; каждый экземпляр сопоставляется с файлом и
матрицей снимка. После упаковки исполнитель открывает сборку и проверяет состав,
зависимости и положения до разблокировки сохранения.

Если подготовка геометрии превысила лимит, ошибку получает только это задание.
Если остановился сам SOLIDWORKS или экспорт EASM, COM-процесс может остаться
запущенным. Перед перезапуском очереди администратор проверяет `progress.json`,
журнал этапа и принадлежность оставшегося скрытого процесса каталогу неудачного
задания. Нельзя завершать интерактивные сеансы других пользователей. Повторный
запуск создаёт отдельное задание; готовые файлы предыдущих сборок сохраняются.
Журналы и `error.json` лежат в каталоге задания. Автоматическая очистка результатов
и полноценная проверка пересечений не реализованы.

## Проверки

```powershell
node --test tests/cad-export.test.mjs tests/cad-export-api.test.mjs
node tests/cad-export-browser.mjs
python services/solidworks-export/test_export.py
npm run typecheck
```

Python-тесты геометрии выполняйте в CAD-окружении с OCP. При отсутствии OCP они
пропускаются; контракт очереди и проверки доступа продолжают выполняться.
Для приёмки конкретной версии SOLIDWORKS дополнительно нужен реальный выпуск
ZIP/EASM, открытие архива на чистом пути со всеми ссылками и просмотр EASM,
включая скрытые компоненты. Наличие установленного API и успешная компиляция
не заменяют этот прогон.

Для повторения приёмочного теста запустите `services/solidworks-export/smoke_export.py` из того же CAD-окружения с аргументами `--root`, `--state`, `--runner`, `--template` и `--part-template`. Выберите отдельный каталог состояния.

Чтобы проверить уже **скачанный** EASM на Windows с установленным eDrawings x64, выполните
`./services/solidworks-export/acceptance/check-edrawings.ps1 -Drawing <файл.easm> -MinimumComponents <число включённых экземпляров>`.
Проверка ждёт сообщения eDrawings об успешной загрузке именно этого файла и запрашивает количество компонентов у просмотрщика.
В счёт eDrawings может входить сама корневая сборка; точное число физических экземпляров содержится в отчёте ZIP.
Параметр `-PreviewJpg <новый файл.jpg>` сохраняет вид из открытого EASM средствами самого eDrawings.

На SOLIDWORKS 2023 проверен выпуск с четырьмя экземплярами. В собранную установку вошли полая труба, кран из нативного SLDPRT и скрытый фланец. Четвёртый экземпляр с отсутствующей моделью попал в отчёт. Тест скачал ZIP, EASM и отчёт через HTTP и проверил, что оба формата относятся к одной сборке и содержимое отчёта в ZIP совпадает с отдельным файлом.

2 ноября 2026 года на рабочем сервере проверена установка на 922 физических экземпляра.
SOLIDWORKS подтвердил положения 801 экземпляра при открытии упакованной сборки;
93 пропущены из-за отсутствующего источника, 28 — из-за неподдерживаемой геометрии.
Первичная сборка и проверка заняли около 28 минут. Из одного задания в браузере скачаны
ZIP (SLDASM, 40 файлов SLDPRT, отчёт) и EASM. Проверены CRC и содержимое архива,
совпадение скачанных файлов с файлами задания, открытие EASM в eDrawings 2023
(802 компонента с учётом корня). Выбор пропущенного насоса во вкладке предупреждений
не изменил готовность сборки и доступность сохранения.
## Штампованные свободные фланцы (02.11.2026)

В компоновке насосной установки свободный фланец за приварным воротником выбирается по каталожной позиции и проверенным размерам. Для принятого исполнения браузер показывает триангуляцию оригинала, а SOLIDWORKS вставляет сам SLDPRT или STEP отдельным именованным компонентом. Готовый файл старой сборки не переписывается. После обновления страницы сборку со старыми фланцами нужно собрать заново. Чертёж и расчёт цен не меняются.

* Для DN40 и DN80 используются оригинальные штампованные SLDPRT из раздела «Штампованные» локальной библиотеки (AISI, PN16). Для DN50, DN65, DN100 и DN125 используются [модели серии LF.G производителя HECO](https://www.heco.de/en/stainless-steel/flanges/loose-plate-flanges/pressed-from-sheet/pn-10-16.html). Локальные DN100/125 обозначены как Ст20; у локального DN125 измеренное отверстие 136 мм меньше OD трубы 139,7 мм.
* DN150 и DN200 PN16 используют только кольцо AISI 304 из [исходного STEP узла Kohler R-358](https://kohler.ch/de/3d-step-dateien). Изготовитель указывает для кольца 1.4301, для внутренней части — 1.4404 ([каталог, с. 111](https://www.datocms-assets.com/103957/1760533751-katalog_rofi_form159.pdf#page=111)). [Скрипт выделения](../scripts/extract-kohler-rings.py) проверяет хеш оригинала, отделяет кольцо на плоскостях контакта и проверяет, что результат — одно валидное твёрдое тело. Воротник выбирается по спецификации. Для DN150 измерены посадка Ø173 и 8 отверстий Ø21,5 на Ø240, для DN200 — Ø225 и 12 отверстий Ø21,5 на Ø295. Это монтажная геометрия; рабочее давление произвольной пары кольцо–воротник отдельно не подтверждается.
* Всего есть 14 привязок к позициям PN10/16. Сверловка DN65 на четыре отверстия совместима с рассматриваемой позицией PN10, но не со старым восьмиотверстным PN16. Неподтверждённая посадка или отсутствие модели дают адресное предупреждение. Плоское кольцо другой серии и параметрический диск не подставляются. Правило не относится к приварным фланцам.
* Исходные и принятые 3D-размеры, монтажная матрица, путь и SHA-256 хранятся в [индексе](../data/stamped-loose-flanges.json). [Скрипт](../scripts/index-stamped-flanges.py) читает твёрдое тело, сверяет положения отверстий, ставит опорную плоскость воротника в X=0 и готовит STL в той же системе координат. PDF [технических данных HECO](https://www.heco.de/webservice/downloads/product-sheet/118/en/heco-product-sheet-118-Stainless-steel-loose-plate-flanges-pressed-from-sheet-PN-10-16.pdf) различает толщину листа и полную высоту. В контрольной сборке DN100 это 4 и 23 мм, DN125 — 6 и 25 мм.
* При чтении сохранённой компоновки обновляется профиль и пересчитываются зависимые группы крепежа. Положение, поворот и видимость оборудования сохраняются. Если раньше выбранной длины хватало, но новый фланец увеличил пакет, подбирается ближайшая достаточная длина той же каталожной серии (тип, резьба, стандарт, покрытие и класс). Замена видна в примечаниях крепежа и отчёте CAD. Явно недостаточный для прежнего соединения крепёж по-прежнему блокируется. Приложение не переписывает сохранённую спецификацию при открытии.
* Для старого статуса «модель фланца отсутствует» редактор заново сверяет штампованное кольцо с исходными размерами позиции, наружным диаметром шейки и диаметром борта сохранённого воротника. В сохранённых вставках поддерживаются обе записи ключа SHA-256: серверная base64url и прежняя шестнадцатеричная. Если прежний клиент уже удалил шаблон автоматической вставки, открытие инструмента восстанавливает его по той же позиции, ID, ревизии, исполнению и длине. Ручная геометрия не заменяется; автокомпоновка не запускается.
* На крупных установках Windows-исполнитель держит корневую сборку открытой и закрывает документ каждой импортированной модели после сохранения именованной копии. Экземпляры вставляются по пути к этой копии. Это ограничивает число одновременно открытых окон SOLIDWORKS на этапе импорта. При проверке готового ZIP исполнитель снова открывает упакованную сборку и сверяет экземпляры.

Проверка на копии установки PS-2026-DBNLRE, задание `5fa871e8-1021-4221-89bc-01e71554ae7c`: в скачанном ZIP восемь LF-114-GPR-1 и четыре LF-139-GPR-1, каждый экземпляр соответствует одному твёрдому телу с металлической окраской. В фактических координатах сборки расстояние между проверенным воротником DN100 и фланцем равно нулю, общий объём тел — 0 мм³. Для двух насосных соединений выбраны 16 шпилек М16×165 вместо М16×160. Всего включено 239 из 245 экземпляров. Четыре концевых воротника DN125, рама и корпус бака по-прежнему в отчёте о пропусках. EASM повторно открыт Windows-исполнителем в eDrawings с проверкой имён компонентов.

Проверка на сохранённой компоновке с семью ONIS MBL 80-250-45/2E, задание `13acda1c-b9be-43cb-808d-81bc53830a11`: браузер отобразил все 56 свободных фланцев (7 DN80, 7 DN100, 28 DN150, 14 DN200). В скачанном ZIP все 56 — отдельные именованные компоненты с одним твёрдым телом, металлической окраской и положением по снимку. Проверены зависимости, целостность архива и совпадение вложенного отчёта с отдельным. Всего SOLIDWORKS подтвердил 899 из 1010 экземпляров. У 30 пропущенных нет исходной модели, включая семь насосов; для 81 не поддерживается построение геометрии. EASM получен из того же задания и открыт в eDrawings: 900 компонентов с учётом корневой сборки.
