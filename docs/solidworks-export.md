# Сохранение компоновки в SOLIDWORKS и eDrawings

1. Завершите компоновку установки в браузере.
2. Выберите **Расчёт → Собрать в SOLIDWORKS**. Исполнитель сохранит отдельный снимок проекта и проверит собранные детали.
3. В инструменте **3D-модель → Предупреждения SOLIDWORKS** посмотрите итог и пропущенные экземпляры. Нажатие на имя переводит редактор к соответствующему компоненту. Для каждого пропуска доступны причина, способ исправления, ID экземпляра, узел и известная позиция спецификации.
4. После готовности используйте **Расчёт → Сохранить 3D**. Выбор **Проект SOLIDWORKS** скачивает ZIP с моделью, зависимостями и файлом `export/report.json`. **Сборка eDrawings** скачивает EASM. Отчёт доступен отдельной ссылкой.

Полная и неполная сборки разрешают сохранение без дополнительного подтверждения. Предупреждения считаются по физическим экземплярам. При отсутствии всех деталей или технической ошибке проверки сборки сохранение блокируется. Все попытки хранятся в отдельных каталогах.

Доступ соответствует 3D-редактору: pro/admin при включённом расчёте геометрии.
В beta функция закрыта. Пока серверный исполнитель не настроен, интерфейс
сообщает, что сервис сборки не подключён.

## Источник компоновки

Единственный источник положений — текущий `station-model.editor.assembly`.
При экспорте не выполняются автокомпоновка, обновление состава, следование
патрубкам, центрирование или масштабирование. Несохранённые ручные правки,
уже переданные редактором в состояние проекта, входят в снимок.

Передаются физические экземпляры, их ID, ID оборудования, выбранные исходные
CAD-модели по SHA-256, параметры собственных деталей и полные преобразования.
Вложенная деталь учитывает базы компонента, детали и исходной модели ровно один
раз. Система браузера — правая, Z вверх, размеры в мм, углы Euler XYZ.
В API SOLIDWORKS передаются строки осей матрицы и перенос в метрах, масштаб 1.
Скрытые элементы остаются в составе; скрытие используется только для видимости.
Информационные строки крепежа не создают повторные физические экземпляры.

SOLIDWORKS фиксирует каждую деталь в полученном положении. Свободное
редактирование положений возможно после снятия фиксации пользователем;
сопряжения на этом этапе не создаются. Перестроение не должно менять положение.
Проверяются число экземпляров и фактические матрицы после перестроения:
допуск переноса 0,0001 мм, элементов вращения 1e-8.
При сборке исполнитель создаёт автономный каталог Pack and Go, закрывает исходные документы и открывает сборку из этого каталога. Он сверяет экземпляры и матрицы и проверяет пути зависимостей. По команде сохранения сервис упаковывает этот каталог в ZIP или открывает сохранённую сборку для экспорта EASM. Готовый формат выдаётся из кэша задания. Ошибку экспорта формата можно повторить без пересборки.

## Актуальность

SHA-256 снимка рассчитывается по составу, идентификаторам и геометрии экземпляров, параметрам и преобразованиям. Перемещения, повороты, замены моделей и изменения размеров требуют новой сборки, в том числе когда правка внесена во время обработки. Камера, выделение, прозрачность и скрытие для просмотра сохраняют доступ к готовому результату. В файле остаётся видимость, зафиксированная при запуске задания. При проверке статуса и перед выдачей файлов сервис сверяет версии исходных CAD, использованных при подготовке. После добавления модели для ранее пропущенной позиции запустите новую сборку.

Статус, ID снимка, перечень пропусков и доступные форматы хранятся на сервере. После перезагрузки браузер сопоставляет результат с текущей компоновкой. Проекты, экспортированные старым исполнителем, можно скачать по существующей ссылке. Для нового меню им потребуется одна сборка.

## Геометрия и ограничения

Браузерные STL не используются для конструкторского экспорта. Исполнитель
разрешает исходные STEP/STP/SLDPRT/SLDASM через серверные реестры и проверяет
SHA-256. Исходные файлы должны находиться в `Equipment` внутри корня библиотеки.
Выбор произвольного пути из браузера не разрешает доступ к другим файлам.

Для труб, колец, фланцев с отверстиями и выступом, воротников, крепежа и
коллекторов с седловыми патрубками создаются аналитические твёрдые тела OCP,
которые SOLIDWORKS импортирует и сохраняет в родном формате. История эскизов
и операций для импортированных тел не восстанавливается. Резьба этих деталей
имеет номинальную поверхность без винтового профиля; примечание входит в задание.

Условные габариты насосов, рам и прочего оборудования не превращаются в
конструкторские детали. Для них нужна реальная модель точного исполнения.
Для неподдерживаемой геометрии, отсутствующего или изменённого исходника, ошибки импорта или построения отдельного элемента исполнитель записывает пропуск в отчёт и продолжает сборку доступных деталей. В отчёте сохраняется каждый пропущенный экземпляр, даже если у нескольких одна модель.
Геометрические предположения коллекторов сохраняются в примечаниях.

Дополнительные проверенные модели можно зарегистрировать в JSON, путь к которому
задаётся только администратором через `CAD_EXPORT_LIBRARY`:

```json
{
  "models": [{
    "equipmentId": "frame-execution-id",
    "parameters": {
      "length": 1200, "width": 600, "height": 80,
      "diameter": 50, "routeOffset": 0
    },
    "source": "Equipment/Frames/approved-frame.SLDPRT",
    "sourceHash": "SHA256_ИСХОДНОГО_ФАЙЛА"
  }]
}
```

Все параметры должны точно совпасть со снимком. Масштабирование готовой рамы
до запрошенных габаритов не выполняется. Для параметрических исполнений рам
нужен отдельный проверенный генератор или подготовленная модель исполнения.

## Запуск Windows-исполнителя

Нужны выделенная свободная Windows-сессия с доступным лицензированным SOLIDWORKS,
.NET 9 x64, Python с зависимостями `services/model-converter/requirements.txt`,
библиотека моделей и шаблоны ASMDOT/PRTDOT используемой версии.
Исполнитель отказывается работать, если SOLIDWORKS уже запущен в доступной сессии.
Не используйте сессию конструктора для автоматической очереди.

Из каталога `frontend`:

```powershell
dotnet build services/solidworks-export/runner/SolidWorksExport.csproj -c Release
```

Если библиотеки API находятся в другом каталоге, задайте
`-p:SolidWorksApiDir="C:\путь\к\SOLIDWORKS\api\redist"`.
Используйте Python существующего CAD-окружения. Задайте в его процессе
`CAD_EXPORT_TOKEN` — случайный серверный секрет длиной не менее 24 символов.

```powershell
python services/solidworks-export/server.py `
  --root E:\PumpStation_Calculator `
  --state E:\PumpStation_Calculator\work\cad-export-state `
  --runner services\solidworks-export\runner\bin\Release\net9.0-windows\SolidWorksExport.exe `
  --template "C:\ProgramData\SOLIDWORKS\SOLIDWORKS 2023\templates\gost-assy.asmdot" `
  --part-template "C:\ProgramData\SOLIDWORKS\SOLIDWORKS 2023\templates\gost-part.prtdot"
```

Команда слушает только `127.0.0.1:8767`. Для удалённого исполнителя нужен
закрытый канал HTTPS между сервером приложения и исполнителем. В браузер
адрес и секрет исполнителя не передаются.

На сервере приложения задайте `CAD_EXPORT_URL=http://127.0.0.1:8767` и тот же
`CAD_EXPORT_TOKEN`. Локальный `preview-full.mjs` передаёт эти переменные в Worker.
При запуске через `start-local.ps1` их можно добавить в личный `full.json`;
саму очередь запускают отдельно приведённой командой.

## Очередь и результат

Задания и входные снимки сохраняются на постоянном диске. Один процесс
исполняет их последовательно; каталог состояния защищён от второго процесса.
Для владельца проекта одновременно допускается одно активное задание.
Повтор одного requestId возвращает то же задание; другой снимок под тем же ID
отклоняется. Максимум 20 активных заданий в общей очереди, вход 16 МБ,
до 30000 физических деталей после раскрытия крепежа и собственных изделий.

API приложения связывает запрос с текущей учётной записью. Получить статус и
скачать результат может только владелец; сервис доступен по серверному секрету.
Скачивание идёт потоком через приложение без публичной ссылки на диск.

Закрытие окна или смена вкладки не останавливает принятое задание. При открытии
«Расчёт» приложение получает его актуальный статус. Перезапуск очереди помечает
прерванные задания ошибкой и требует явного повторного формирования.
После тайм-аута очередь останавливает дальнейшее исполнение: COM-процесс может
оставаться живым, поэтому администратор проверяет сессию перед перезапуском.
Журналы и `error.json` лежат в каталоге задания. Автоматическая очистка результатов
и полноценная проверка пересечений не реализованы.

## Проверки

```powershell
node --test tests/cad-export.test.mjs tests/cad-export-api.test.mjs
node tests/cad-export-browser.mjs
python services/solidworks-export/test_export.py
npm run typecheck
```

Python-тесты геометрии выполняйте в CAD-окружении с OCP. При отсутствии OCP они
пропускаются; контракт очереди и проверки доступа продолжают выполняться.
Для приёмки конкретной версии SOLIDWORKS дополнительно нужен реальный выпуск
ZIP/EASM, открытие архива на чистом пути со всеми ссылками и просмотр EASM,
включая скрытые компоненты. Наличие установленного API и успешная компиляция
не заменяют этот прогон.

Для повторения приёмочного теста запустите `services/solidworks-export/smoke_export.py` из того же CAD-окружения с аргументами `--root`, `--state`, `--runner`, `--template` и `--part-template`. Выберите отдельный каталог состояния.

На SOLIDWORKS 2023 проверен выпуск с четырьмя экземплярами. В собранную установку вошли полая труба, кран из нативного SLDPRT и скрытый фланец. Четвёртый экземпляр с отсутствующей моделью попал в отчёт. Тест скачал ZIP, EASM и отчёт через HTTP и проверил, что оба формата относятся к одной сборке и содержимое отчёта в ZIP совпадает с отдельным файлом.
