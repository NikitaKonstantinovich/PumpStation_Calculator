# Заведение позиций

Пункт бургер-меню **«Заведение позиций»** открывает вкладку **«Заведение насоса»**.
Доступен администратору в full и beta, прямая ссылка — `/?view=item-entry`.

Обязательно только наименование модели. Производитель, серия, тип, артикул,
исполнение, гидравлика, электрика, патрубки, материалы, габариты, масса, цена,
наличие, источники и вложенные файлы необязательны. Пустые числовые значения
хранятся как `null`, без подстановки нулевых характеристик. Сохранённую запись
можно найти в списке слева и дополнить. Проверяются только заполненные данные.

DN всасывающего и напорного патрубков, типы соединений и PN передаются
в «Расчёт DN» отдельно для каждого патрубка и контура, включая ранее
сохранённые ручные записи. Данные берутся из текущей карточки без повторного
импорта каталога. Для многоступенчатого насоса DN арматуры по умолчанию
учитывает соответствующий патрубок. Ручные поправки патрубков в проекте
имеют приоритет; кнопка «Патрубок из каталога» возвращает данные карточки.
Если заполнен только DN, он отображается, а тип соединения запрашивается
отдельно. PN патрубка не заменяет неизвестный предел давления на входе насоса.

Кривые Q–H, КПД, мощности и NPSH вводятся по одной паре значений на строку,
через точку с запятой. Допустимы десятичные точка и запятая. Точки сортируются
по расходу, повторный расход и недопустимые числа отклоняются. Пустая кривая
или одна точка не мешают сохранению. В подбор насос попадает при наличии
минимум двух корректных точек Q–H и включённых флагах активности и подбора.

Для изображения, чертежа и 3D-модели есть отдельные области загрузки. Файл
выбирается на компьютере или перетаскивается в нужную область. Программа сама
назначает имя в каталоге, показывает исходное имя и прогресс, позволяет заменить
файл либо убрать привязку. После загрузки нужно сохранить запись насоса.
Одинаковые исходные имена не перезаписывают файлы. Старые сохранённые пути
сохраняются как прежние привязки; вместо них можно загрузить новый файл.

Изображения: PNG/JPG/WEBP/GIF/BMP, до 20 МБ. Чертежи: те же форматы,
PDF/DWG/DXF, до 30 МБ. 3D: STEP/STP/STL/IGES/IGS/SLDPRT/SLDASM/X_T/X_B/OBJ/
GLB/GLTF/EPRT/EASM, до 100 МБ. Загрузка потоковая, файл сначала записывается
во временное имя и появляется в каталоге только после полного сохранения.
Подготовка геометрии и присоединений 3D остаётся отдельным процессом.

В full файлы хранятся в `pump-files` рядом с `PROJECT_STATE_DIR`, например
`E:\PumpStation_Data\full\pump-files`, в подкаталогах image/drawing/model.
Каталог можно задать через `PUMP_FILES_DIR`. В локальной beta по умолчанию
используется `pump-files` внутри её каталога состояния. Сборки не содержат
загруженные файлы и не удаляют их при обновлении. Временные непривязанные
загрузки не удаляются автоматически; «Убрать из записи» снимает только привязку.

Метаданные хранятся в D1 `manual_pump_files` (`0013_manual_pump_files.sql`).
`POST /api/pumps/files` требует admin; `GET/HEAD /api/pumps/files/:id` требует
вход. Имена в файловой системе генерирует сервер; исходное имя хранится в
метаданных. Проверяются формат, размер, длина потока и сигнатуры изображений/PDF.
Серверный обработчик использует внутреннюю привязку `PUMP_FILES`, подключённую
в `preview-full.mjs` и `preview-beta.mjs`, без отдельного публичного порта.
Карточка насоса показывает ссылки на вложения; PDF/CAD отдаются как скачивание.

Записи хранятся в таблице D1 `manual_pumps`, миграция `0012_manual_pumps.sql`.
Схема также идемпотентно инициализируется при первом запросе. Исходные
импортированные каталоги не переписываются. Ручные записи добавляются к
рабочему каталогу в full, beta и поиске AI-assistant. После сохранения каталог
текущего рабочего пространства обновляется сразу; в других вкладках — после
перезагрузки страницы.

`GET /api/pumps` возвращает насосы авторизованным пользователям;
`GET /api/pumps?manage=1`, `POST` и `PATCH` доступны только admin. API проверяет
источник записи и заполненные поля. Обновление требует актуальную ревизию,
конфликт возвращает 409. Повторная ручная запись с теми же производителем,
моделью и исполнением отклоняется. Данные в форме остаются при ошибке сохранения.
