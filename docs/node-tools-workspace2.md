# Нодовые инструменты и Рабочее пространство 2

Первый инструмент — «Настройки проекта». Его параметры, условия, форма и проверочные примеры хранятся в редактируемом определении. Расчёт и форма используют общий исполнитель графа и renderer в предпросмотре и рабочем пространстве.

## Запуск

Из E:\PumpStation_Calculator\frontend выполните npm ci и npm run build:full. Для существующего изолированного локального профиля примените отсутствующие миграции drizzle/0017_node_tools.sql и drizzle/0018_node_catalog_snapshots.sql через Wrangler с его каталогом состояния. Для пустой базы примените все миграции по порядку.

Запустите настроенный полный профиль командой npm run start:local. Войдите как admin и откройте главное меню → «Нодовый редактор». Адрес редактора — /?view=node-editor. Адрес рабочего режима — /?view=workspace2.

Старый Geometry Nodes доступен через пункт «Алгоритм станции». Workspace 2 сохраняет собственные параметры и ссылки на версии в отдельной части проекта. Публикации инструментов имеют отдельную историю.

## Общий граф продукта

Редактор открывает один корневой граф. Каждый корневой Instrument является инструментом Workspace 2; вложенный Instrument остаётся внутренней группой. Список «Инструмент» фокусирует корневую карточку, «Показать все инструменты» возвращает общий план. Стабильный ID экземпляра сохраняется при переименовании. Порядок и доступность задаются в «Свойства → Инструмент продукта» и не зависят от положения ноды.

«＋ Инструмент» создаёт карточку на этом же полотне и внутренний каркас: собственный источник Workspace 2, форму, команду сохранения и результат. Откройте его кнопкой «Раскрыть Instrument». «Новый параметр» автоматически подключается к собственному источнику экземпляра. «Собрать Instrument» доступно внутри раскрытого инструмента и объединяет выбранные внутренние узлы в группу.

Состав вкладок выводится из корневых экземпляров, отдельного редактируемого реестра нет. Отключённые и удалённые инструменты сохраняют прежнее состояние в архиве проекта. Исторические публикации исполняются в прежнем режиме. При открытии старого черновика редактор строит совместимое представление общего графа; оно сохраняется только вашим действием.

В Workspace 2 нажмите «Применить актуальную версию продукта». Все активные инструменты закрепляются одной публикацией и версиями базовых данных/каталога. Миграция сохраняет совместимые пользовательские значения; постоянные и вычисляемые параметры берутся из определения. При прежних разных версиях инструментов отчёт явно сообщает о переходе к выбранной общей публикации. «Сохранить значения» сохраняет согласованное состояние продукта штатным сохранением проекта. Публикация сама не переводит старые проекты на новую версию.

## Проверка первого инструмента

1. Откройте «Настройки проекта», раскройте Instrument колёсиком или кнопкой «Раскрыть Instrument».
2. Внутри видны источники проекта и базовых значений, параметры, логические правила и сборка формы. Два контура используют определение «Исходные данные контура». При изменении определения параметра видны пути его экземпляров.
3. Переключите тип установки в предпросмотре. Совмещённая установка открывает второй контур. Пожаротушение с жокей-насосом открывает его контур.
4. Добавьте «Новый параметр». По умолчанию создаётся строковое «Обозначение установки» с устойчивым ключом designation. Внутри настроек редактор связывает его с источником данных, полем и свободным слотом формы.
5. Соединяйте ноды перетаскиванием выходного порта на вход. Во время перетаскивания появляются скрытые входы, подсветка совместимости и причина отказа. Escape отменяет провод; занятый вход требует подтверждения замены. Для скрытых выходов используйте ПКМ → «Передать атрибут…». Расчётные провода синие, привязки параметров фиолетовые, команды сохранения охристые.
6. В свойствах экземпляра меняйте заголовок раздела, подпись поля, число колонок сетки. Нажатие поля в предпросмотре приближает соответствующий узел. Выбор узла подсвечивает поле.
7. Нажмите «▷ Проверить». Отчёт показывает результаты встроенных примеров и план команды записи. Через «Определение» можно отредактировать примеры в JSON.
8. Сохраните черновик и опубликуйте. В Workspace 2 заполните обязательные параметры и нажмите «Сохранить значения». Сохранение проекта использует существующий механизм ревизий. После перезагрузки значения восстанавливаются.
9. Новая публикация применяется действием «Применить актуальную версию». Совместимые значения сохраняются, требующие преобразования параметры перечисляются в сообщении. Версии и откат доступны в редакторе.

## Всегда чистая вода, поле скрыто

1. В редакторе выберите в списке «Найти параметр…» параметр «Перекачиваемая среда» нужного контура.
2. В основных свойствах выберите «Источник значения» → «Постоянное». Для общего определения просмотрите список использований и подтвердите изменение для обоих контуров.
3. Выберите «Постоянное значение» → «Чистая вода». Выключите «Показывать в форме». Исполняемое значение будет water; нода поля, её положение, подпись и ширина сохраняются.
4. В режиме «Предпросмотр на тестовых значениях» поле сразу исчезает. В дереве «Действующие данные инструмента» проверьте main.medium и secondary.medium (второй контур виден в данных при активной совмещённой установке).
5. Нажмите «▷ Проверить», затем «Сохранить» и «Опубликовать». В Workspace 2 нажмите «Применить актуальную версию» и сохраните значения. Миграция уберёт прежние переопределения medium = wastewater. Предыдущие значения доступны в истории проекта; старые версии используют прежний граф.
6. Для возврата поля найдите параметр через список либо скрытое поле в «Дереве формы», включите «Показывать в форме». Постоянное значение отобразится в недоступном для пользовательского изменения поле.

Чтобы убрать подпись «Базовые значения» или другое происхождение под конкретным полем, выберите поле в предпросмотре (либо в свойствах параметра нажмите «Свойства поля») и выключите «Показывать источник значения». Само поле, его значение и привязка сохраняются; происхождение остаётся в инспекторе. По умолчанию подписи включены, в том числе у существующих определений. Чтобы применить настройку в Workspace 2, опубликуйте граф, примените актуальную версию инструмента и сохраните значения.

Чтобы скрыть подписи источников сразу у всех полей инструмента, нажмите «Свойства формы» и выключите «Показывать источник значения» у ноды «Форма инструмента». Настройка распространяется на вложенные контуры и разделы. При обратном включении учитываются индивидуальные настройки полей: отдельно скрытые подписи остаются скрытыми. По умолчанию общий переключатель включён. Инспектор сохраняет происхождение значений при любом положении переключателя. Публикация и применение версии выполняются как для изменения отдельного поля.

## Источники и просмотр данных

«Ввод пользователя» использует текущие/сохранённые значения, затем базовые и начальное. Начальное значение не переопределяет сохранённое. «Постоянное» берёт отдельное значение из определения. «Вычисляется» получает типизированный выход либо безопасное выражение с объявленными входами; созданную функцию можно раскрыть на полотне. «Данные источника» читает атрибут зарегистрированных данных Workspace 2 или базовой публикации. Атрибут должен иметь совместимый контракт параметра; $.name учитывает область конкретного контура. Источник Workspace 2 должен ссылаться на другой пользовательский ввод, который сохраняется после миграции.

При смене режима неиспользуемые входные связи параметра отключаются. Пользовательские связи сохраняются в служебных данных черновика и восстанавливаются при возврате пользовательского режима. Вычислительная нода остаётся доступной после отключения, её можно подключить повторно.

Перечисления показывают названия вариантов. Числовые поля принимают запятую и точку; пустое значение, ноль и false различаются. Сервер проверяет режим и фактическую роль независимо от доступности поля в браузере.

Наборы данных инспектора: тестовый предпросмотр с явно выбранной симуляцией роли, черновик на сохранённых входах проекта с ролью сессии и точный результат последней серверной пробы. Последний результат хранит роль и версии источников той пробы; после редактирования графа он помечается устаревшим. Сохранённый набор и результат пробы доступны для просмотра. Значения редактируются в режиме тестового предпросмотра.

Дерево данных поддерживает поиск в показанной выборке, копирование пути и полного значения. На уровень отображается до 50 элементов с указанием полного количества; инспектор не перечисляет неограниченные коллекции. При наведении на порт или провод доступны тип, единица, значение и происхождение.

Выбор параметра или поля выделяет цепочку. Действия «К источнику» и «К получателям» сохраняют адрес основного или второго контура. Хлебные крошки возвращают к контейнерам. Выбор на полотне прокручивает предпросмотр и открывает свёрнутый раздел. Ширина предпросмотра регулируется отдельно. Delete удаляет выбранную ноду с подтверждением, F2 переименовывает экземпляр, Ctrl+Z отменяет изменение графа. В текстовых полях сохраняются обычные команды редактирования.

## Ноды

Данные — зарегистрированный источник, параметр, константа, чтение атрибута, сборка и объединение объектов.

Правила — сравнение, логическое И, условный выбор, формула, проверка.

Интерфейс — форма, раздел, сетка, поле параметра, видимость и доступность, сообщение.

Команды — сохранение Workspace 2. В пробе команда представлена как план записи. Рабочая форма передаёт подтверждённые изменения штатному сохранению проекта.

Вложенность — составные Instrument и создание нового определения из выбранных узлов.

Числовые параметры поддерживают float и int, границы и единицы. Ввод принимает десятичную точку и запятую. Пустое значение, 0 и false обрабатываются отдельно. Допустимы строки, перечисления и логические значения. Типы объектов и массивов могут содержать описания полей и элементов.

## Расчёт DN, конструктор коллекторов и спецификация

Новые инструменты собираются на общем полотне в цепочку: **Настройки проекта → Подбор насосов → Расчёт DN → Конструктор коллекторов → Спецификация**. Расчёт DN также получает настройки проекта напрямую. Из подбора передаются подтверждённое исполнение насоса и его условия выбора; изменение условий или снимка каталога требует повторного подтверждения насоса.

В редакторе нажмите **«Готовые инструменты»** и последовательно добавьте:

1. **«Расчёт DN»** — выберите настройки проекта и источник подбора. Инструмент рассчитывает диаметры, скорости и соединения, сохраняет ручные DN, PN, материал и настройки арматуры.
2. **«Конструктор коллекторов»** — выберите созданный расчёт DN. Сохраняются карточки всасывающего и напорного коллекторов, размеры, конфигурация, состав, сварка, стоимость и действия проверки/сохранения в базе.
3. **«Спецификация»** — выберите конструктор. Таблица сохраняет разделы, количества, цены, предупреждения, выбор вставок и изделий гидравлики, а также выгрузку CSV/XLSX. Дополнительные ручные позиции хранятся в параметре инструмента.

Шаблоны добавляют отдельные корневые Instrument и соединяют их. Через **«Раскрыть Instrument»** доступны редактируемые этапы: подготовка исходных данных, расчёт контуров, рекомендации и конфигурация коллекторов, расчёт материалов и стоимости; в спецификации — насосы, шкаф, рама, линии, опции и готовность состава. Связи и параметры этих этапов можно менять. Сами панели DN, конструктора и таблицы реализованы встроенными компонентами: их содержимое и привязки задаются графом, но каждый элемент внутренней разметки пока не представлен отдельной UI-нодой.

Выбор исполнения вставки в спецификации изменяет тот же параметр настроек DN, а выбор гидравлических изделий — общую комплектацию установки в инструменте DN. Привязки проходят через конструктор, поэтому изменения пересчитывают зависимые инструменты, не создавая отдельной скрытой копии настроек. Незавершённый состав допускает сохранение черновика; ошибки готовности остаются в таблице и экспорте, а статус «Спецификация готова» не выставляется.

Нода **«Справочники комплектации»** использует закреплённый снимок комплектующих, шкафов, вставок, каталога коллекторов и базовых правил. В предпросмотре обновление выполняется кнопкой **«Обновить справочники комплектации»**; для рабочего проекта применяется согласованная версия продукта и источников. Старый снимок не заменяется текущим автоматически. Отсутствующие данные и цены показываются явно.

Для совмещённой установки или пожарной станции с жокей-насосом нужен **отдельный инструмент подбора второго контура**. Укажите его в поле **«Подбор насоса второго контура»** при добавлении DN. Само включение второго контура в настройках не создаёт второй подтверждённый выбор насоса.

Редактор доступен администратору. В рабочем режиме роль `base` использует стандартный расчёт: ручные изменения DN, материала и конфигурации коллекторов, а также ручные позиции спецификации требуют `pro` или `admin`; изменение опций комплектации доступно с `plus`. Сервер проверяет права при сохранении независимо от доступности элементов формы.

После сборки проверьте предпросмотр, сохраните и опубликуйте граф. В Workspace 2 нажмите **«Применить актуальную версию продукта»**, затем сохраните значения проекта.

## Границы этапа

Источники ограничены данными Workspace 2, версиями базовых значений, зарегистрированным новым каталогом насосов и закреплёнными справочниками комплектации. Произвольный JavaScript и произвольные внешние подключения относятся к следующему этапу. Проверочные примеры редактируются в JSON. Для использования нового физического метода можно расширить библиотеку типизированных операций.

Текущая форма сохраняет значения по явной команде. Незавершённый числовой ввод остаётся в поле до корректного подтверждения. Параметры отключённых контуров и опций сохраняются, действующий выход формируется правилами графа.


## Как вручную собрать «Подбор насосов»

Подробные шаги, контракты и таблица проводов находятся в docs/node-pump-selection-manual.md. Библиотека подготовлена; готовый подбор не добавляется в пользовательский черновик автоматически.


### Инженерная карточка насоса

Карточка выводит явный состав инженерных характеристик выбранного исполнения. Исходная запись, служебные идентификаторы и происхождение данных сохраняются в административном инспекторе. Справочные размеры модели и размеры, связанные с исполнением, имеют разные подписи применимости. Символы чертежа и исходные кривые доступны в свёрнутых разделах.

В ноде `ui.pumpDetail` («Инженерная карточка насоса») доступны порядок и видимость разделов, основные поля шапки, показ паспортных характеристик, рабочей точки и цены, начальное раскрытие подробностей. «Показывать источник значения» наследует ограничение формы инструмента. Настройки записываются в документ графа; один компонент используется в предпросмотре и Workspace 2.

`pump.chartPoint` сохраняет прежний выход `point` и добавляет `details` («Рабочая точка с условиями расчёта»). Подключайте его через выход гидравлического инструмента к входу `operatingPoint` ноды `pump.detailData` соответствующей карточки. Передаются выбор исполнения, модель, набор кривых, снимок, контур, условия, частота и метод расчёта. Карточка использует общее пересечение кривых, не рассчитывая его заново. Дополнительные показатели интерполируются только внутри исходных диапазонов; NPSHr при пересчёте частоты не выдумывается.

При первом открытии старого графа добавляются недостающие настройки и связь с единственным подходящим гидравлическим инструментом того же источника выбора. Существующие связи не заменяются. При нескольких подходящих графиках администратор выбирает связь вручную. Сохранение и публикация обновляют существующие инструменты, сохраняя их идентификаторы. Закреплённые версии сохранённых проектов не переключаются автоматически.

Для электрических режимов и температурных ограничений обновите снимок каталога в редакторе. Адаптер читает все подтверждённые сочетания напряжения, тока, фаз и схемы; цена `net` остаётся закупочной и повторно на скидку не уменьшается. Температура для дополнительного исполнения не считается подтверждённой характеристикой выбранного насоса. Дата цены вынесена в подробности; техническая запись источника доступна в инспекторе. Если база содержит только служебную ссылку, название коммерческого документа не выдумывается.


## Межосевые расстояния из нового каталога

Внутри «Расчёта DN» добавлены две независимые цепочки: «Данные компоновки насосов» → «Поиск правила межосевого расстояния» → «Расчёт межосевого по габаритам» → «Проверка зазора» → «Результат межосевого расстояния». В свойствах первой ноды задаётся направление размещения относительно потока через насос. Неизвестная ориентация явно сохраняется как «Не задано». Количество установленных насосов включает рабочие и резервные.

Результат передаётся в рекомендации коллекторов. Карточка насоса получает итоговую компоновку из конструктора, включая отдельные ручные решения для всасывающего и напорного коллекторов. Межосевое расстояние здесь — шаг осей соседних насосов вдоль коллектора, а не паспортный размер одного насоса.

Новый снимок каталога сохраняет связи `legacy_model_map` и `legacy_variant_links` с их областью доказательства. ID нового исполнения не заменяется старым ID. Модельная связь не подтверждает габариты каждого двигателя. Точные заводские связи проверяются отдельно от модельных и неоднозначных. Мощность берётся из текущего исполнения. Применимое правило сохраняет прежнее расстояние; консервативный шаг группы автоматически не уменьшается.

Точный результат содержит источник, статус, правило и его закреплённую версию, снимок каталога, исполнение двигателя, ориентацию, число насосов, использованные вылеты и зазор. Данные доступны в инспекторе. Старый снимок без связей не дополняется данными последнего каталога: обновление источника выполняется явно. Закреплённая версия правил не заменяется seed или текущей публикацией.

При отсутствии применимого результата расчёт допускается только по подтверждённым вылетам полного насоса в направлении соседнего: корпус, двигатель, клеммная коробка и выступы. Требуются точное исполнение, двигатель, ориентация, источник и версия геометрии. Для соседних одинаково ориентированных насосов используются обращённые правый и левый вылеты. Симметричный случай сводится к `S = max(minimum, ceil((2R + gap) / increment) × increment)`. Смешанный ряд разных насосов требует отдельной парной компоновки и здесь автоматически не рассчитывается. D1/D2, межфланцевое расстояние и размеры основания сами по себе не являются полным вылетом.

Параметры `minimum`, `gap`, `increment` редактируются в разделе «Базовые значения → Межосевые расстояния» и публикуются вместе с правилами. Исходные значения приложения — 400/150/50 мм; это политика приложения, не универсальный норматив. В версионируемом контракте правила предусмотрены `variantIds`, `applicability.motorKeys`, `applicability.orientations` и подтверждённая `geometry`; существующие публикации не расширяются задним числом.

Ручное значение и подтверждение доступны с уровня pro. Подтверждение привязано к исполнению, двигателю, снимку, геометрии, ориентации, количествам, правилу и расстоянию. После изменения исходных данных число сохраняется, но требуется новое подтверждение. Неизвестные размеры остаются неизвестными. Известный недостаточный зазор блокирует расчёт даже после ручного подтверждения. Сервер заново читает закреплённый снимок и правила; присланные клиентом размеры и статусы не принимаются на веру.

Проверка источника pump-catalog/v0.22 от 09.11.2026: найдены прежние правила для 2454 исполнений, но подтверждение конкретного двигателя отсутствует — статус «Условно»; для 2104 исполнений нет достаточных данных (включая одно прежнее правило со статусом «Недостаточно данных»); у 19 неоднозначное соответствие. Новые геометрические расчёты на этих данных не выполнялись. У модели 422 три исполнения: 1100105106 (IE3, в источнике обозначено CDM65-10FSWPC), 1100119802 (IE3) и 1100198970 (IE4), по 5,5 кВт. Для всех найдено правило research-9, 750 мм, но применимость остаётся условной. Подмены размеров конкретного двигателя групповым паспортом нет.

## Второй контур: три связанных инструмента

В редакторе откройте «Готовые инструменты», выберите «Добавить инструменты второго контура» и источник «Настройки проекта». Команда добавляет три отдельные корневые ноды с собственными определениями: «Подбор насоса (2 контур)», «Гидравлическая кривая (2 контур)», «Карточка насоса (2 контур)». Повторное применение к тем же настройкам возвращает созданный подбор, не меняя его ручных правок и не создавая дубликаты. Если часть группы удалена или входы второго контура DN заняты другим подбором, редактор сообщает об этом, сохраняя связи.

Результат настроек и представление полей `scope=secondary` подаются во второй подбор. Поля Q/H и количества доступны только для просмотра. Далее идут зависимые фильтры, собственная сортировка, явный статический напор и таблица с закупочной ценой и фактической рабочей точкой. Старший фильтр сохраняет подходящие значения зависимых фильтров. Условия для графика извлекаются из того же набора кандидатов, который поступил на проверку выбранного исполнения.

Второй график получает выбранное исполнение, подтверждение и условия из второго подбора. Привязки редактирования Q/H берутся только из представления второго контура. Карточка получает это исполнение, контекст рабочей точки из второго графика и компоновку из существующего конструктора коллекторов. Второй подбор подключается к входам «Выбранное исполнение — второй контур», «Статус подтверждения — второй контур» и «Условия подбора — второй контур» существующего расчёта DN. Расчёт DN, коллекторы и спецификация остаются едиными.

Нода «Второй контур используется» следует правилам совмещённой установки и пожарной установки с жокей-насосом. «Выполнять только активный контур» лениво вычисляет каждый выход: при отключении не запускает подбор, график и карточку. Интерфейс показывает «Второй контур не используется». Настройки сохраняются, подтверждение насоса отзывается; после включения необходимо снова выбрать исполнение в таблице. Отключённый контур не включается в спецификацию. Резерв учитывается в количестве оборудования, а рабочая характеристика строится только для работающих насосов.

Сохраните черновик и опубликуйте граф. В сохранённом проекте откройте «Рабочее пространство 2» и явно нажмите «Применить актуальную версию продукта». Публикация не переключает сохранённые проекты автоматически. Условия и независимые состояния проверяются в `tests/node-tools-secondary.test.mjs` вместе с общими тестами расчётов.
