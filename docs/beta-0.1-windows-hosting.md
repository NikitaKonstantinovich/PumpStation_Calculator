# Beta 0.1 на Windows-ПК

Конфигурация на 25.10.2026: **https://188.242.166.168/** (без домена), LAN ПК
`192.168.0.186`, приложение `127.0.0.1:3005`, Caddy на TCP 80/443.
На скриншоте пользователя оба правила проброса включены. Закрепите LAN-адрес
ПК в DHCP роутера, чтобы они продолжали указывать на этот компьютер.

## Что подготовлено и проверено

- Собранная beta работает в Miniflare/workerd с D1 из `.wrangler/state`.
  Это существующая база разработки. Запуск всегда использует `--migrations skip`.
- Явный `--public-origin https://188.242.166.168` задаёт адрес ссылок
  и восстанавливает HTTPS-origin только для точно совпадающего Host.
  Произвольные `X-Forwarded-*` не меняют источник запроса. Вход через localhost
  продолжает работать. Cookie сохраняет Secure, HttpOnly и SameSite=Lax.
- HTTP-тесты проверяют вход, управление пользователями, отклонение чужого
  Origin, приватные файлы и ограничения beta как напрямую, так и за прокси
  с доменом и IP. Все 14 тестов beta-release, beta-http и public-origin проходят.
- `deployment/windows/Caddyfile` проксирует все запросы через Worker.
  Прямая раздача `dist/client` недопустима: она обойдёт проверку доступа.
- Caddy 2.11.7 установлен в `work/hosting/caddy.exe`; архив Windows amd64
  проверен по SHA-512 из официального файла checksums выпуска.
- Установлен автозапуск при входе в Windows. Правило Windows Firewall
  `PumpStation-Beta-Caddy-HTTPS` включено: только Caddy, входящие TCP 80/443.
- Получен доверенный сертификат Let's Encrypt YE2 с SAN `IP Address:188.242.166.168`.
  Действует с 24.10.2026 20:48:14 UTC до 31.10.2026 12:48:13 UTC.
  Caddy настроен на профиль ACME `shortlived` и автоматическое продление.
  Проверка curl с проверкой цепочки и IP, без `-k`, получила HTTP 200.
- Внешние проверки HTTPS 25.10.2026 получили HTTP 200: главная страница
  из Индии и Украины, `/api/release` из Сербии и Сингапура.
  Отчёты: [главная](https://check-host.net/check-report/5333bccbk478),
  [версия beta](https://check-host.net/check-report/5333bcd3k29b).
  Узлы США и Японии сообщили таймаут;
  доступность подтверждена перечисленными четырьмя внешними узлами.

Прежний `pumps-beta.tplinkdns.com` исключён из активной конфигурации Caddy:
DNS TP-Link возвращал NXDOMAIN/SERVFAIL при проверке сертификата.
Аналогичный сбой описан в
[сообществе Let's Encrypt](https://community.letsencrypt.org/t/tplinkdns-com-can-renew-certificate/251648).
Текущий доступ по IP от этого DNS не зависит.

Приложение использует Cloudflare bindings; обычный `vinext start` их не заменяет.
Для первого ограниченного тестирования используется существующий workerd/D1
за Caddy. Это не установка production-службы: Miniflare предназначен для
[локальной разработки](https://developers.cloudflare.com/workers/local-development/).
Долговременное размещение требует поддерживаемой платформы, службы с
восстановлением после сбоя, резервного копирования и проверки нагрузки.

## Запуск

Из PowerShell:

```powershell
cd E:\PumpStation_Calculator\frontend
.\scripts\beta-server.ps1 -Action StartLocal
```

Это запускает только приложение. Для HTTPS после настройки Clash и firewall:

```powershell
.\scripts\beta-server.ps1 -Action Start
.\scripts\beta-server.ps1 -Action Status
```

Остановка запущенных этим скриптом процессов:

```powershell
.\scripts\beta-server.ps1 -Action Stop
```

Скрипт проверяет PID, время запуска и путь перед остановкой процесса.
Неизвестный процесс на занятом порту он не завершает. Запуск повторять безопасно.
Для обновления: Stop, `npm run build:beta`, затем Start. Если после остановки
Windows ещё удерживает файл каталога, повторите сборку после освобождения файла.
Базу и каталог `work/hosting/caddy-data` не удалять при обновлении.

## Windows Firewall и HTTPS

Один раз в **PowerShell от имени администратора**:

```powershell
& 'E:\PumpStation_Calculator\frontend\scripts\enable-beta-firewall.ps1'
```

Правило разрешает только `work/hosting/caddy.exe` и входящие TCP 80/443.
Порт 3005 остаётся доступен только на самом ПК. Для удаления именно этого правила:

```powershell
Remove-NetFirewallRule -Name PumpStation-Beta-Caddy-HTTPS
```

Caddy получает и продлевает сертификат автоматически, если этот публичный IP
по-прежнему принадлежит подключению, а TCP 80/443 доходят до Caddy.
IP-сертификат Let's Encrypt действует около 160 часов; автоматическое продление
включено. См. [IP-сертификаты Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability).
Глобальный `default_sni 188.242.166.168` нужен для клиентов без SNI за NAT.
Сертификаты хранятся в `work/hosting/caddy-data`, журналы — в `work/hosting`.
Папка `work` исключена из Git. Caddy не публикует служебные файлы или БД.

Внешние проверки уже подтвердили доступность. Перед рассылкой сотрудникам
проверьте вход своей учётной записью по `https://188.242.166.168/` с телефона
через мобильный интернет, без Wi-Fi. Реальные пароли пользователей при
автоматической проверке не использовались; вход проверен на изолированной БД.
Проверка из домашней сети может зависеть от NAT loopback роутера.

Статичность белого IP у провайдера не подтверждена. Если IP изменится,
обновите адрес в `scripts/beta-server.ps1` и два места в
`deployment/windows/Caddyfile` (адрес сайта и `default_sni`), затем выполните
Stop и Start. Caddy запросит сертификат для нового IP; сотрудникам понадобится
новая ссылка. Проброс 80/443 на прежний LAN-адрес менять не требуется.

## Clash Verge

На ПК обнаружен Clash Verge Rev 2.5.8: Rule, TUN/gVisor, DNS fake-ip,
`find-process-mode: always`. Глобальный Script.js уже содержит исключения
Steam, Edge и Valheim. В его `main(config)` добавьте перед `return config;`:

```javascript
  const pumpRules = [
    "PROCESS-NAME,caddy.exe,DIRECT",
    "PROCESS-NAME,workerd.exe,DIRECT",
    "IP-CIDR,188.242.166.168/32,DIRECT,no-resolve",
    "IP-CIDR,127.0.0.0/8,DIRECT,no-resolve",
    "IP-CIDR,192.168.0.0/24,DIRECT,no-resolve"
  ];
  config.rules = [...pumpRules, ...(config.rules || [])];
```

Фрагмент сохраняет существующие правила и исключает из VPN Caddy и workerd,
который исполняет Worker. Node обслуживает локальную обвязку. Правила для
процессов уже добавлены при первоначальной настройке; правило для публичного IP
можно добавить для прямого доступа браузера на этом ПК. Для IP настройки DNS
не требуются. Сохраните скрипт и примените профиль/перезапустите ядро.
В разделе соединений Clash новые исходящие соединения Caddy/workerd должны
показывать DIRECT. TUN и Rule можно оставить включёнными.
Правила DIRECT определяют исходящую маршрутизацию; работоспособность входящих
соединений всё равно проверяется отдельно через мобильную сеть.

Справка: [расширения Clash Verge](https://www.clashverge.dev/guide/extend.html),
[правила mihomo](https://wiki.metacubex.one/en/config/rules/),
[DNS mihomo](https://wiki.metacubex.one/en/config/dns/).

## Эксплуатация

Автозапуск установлен для пользователя N1kit: ярлык `PumpStation Beta.lnk`
в пользовательской папке автозагрузки запускает `scripts/beta-autostart.ps1`
без видимого окна. Он запускает приложение и Caddy при входе пользователя
в Windows; до входа в учётную запись сервер автоматически не стартует.
Журналы: `work/hosting/autostart.log` и `autostart-launch*.log`.
При временной ошибке выполняются ещё две попытки через 10 секунд.
Запуск через этот сценарий проверен 25.10.2026: сценарий завершился успешно,
приложение и Caddy остались запущены, HTTPS `/api/release` вернул 200,
а `/api/users` без входа — 401. Ожидание ограничено процессом запуска,
поэтому сценарий не остаётся висеть до остановки серверных процессов.
Чтобы отключить автозапуск, откройте `shell:startup` через Win+R и удалите
только ярлык `PumpStation Beta`. Это не удаляет приложение, базу и сертификаты.
Пока сотрудники тестируют приложение, ПК должен быть включён и не уходить в сон.
Перед изменением схемы делайте SQLite backup через backup API (включая данные
WAL), проверяйте восстановление на отдельной БД. Не копируйте только живой
.sqlite как единственный способ резервного копирования.

Восстановление пароля по почте требует RESEND_API_KEY и EMAIL_FROM в окружении
процесса запуска; APP_BASE_URL уже задаётся публичным HTTPS-адресом.
Без почты создание пользователей и смена пароля доступны администратору.
