# Масса и патрубки CNP

Проверено 24.09.2026. Данные добавлены в `public/pumps.json`, `records.json` и
`database/pumps-merged.sqlite`; используются обеими карточками насоса.

| Серия в базе | Всего | Масса, кг | Патрубки |
| --- | ---: | ---: | --- |
| CDM | 374 | 374 | всасывающий и напорный |
| CHLF | 28 | 28 | резьба G, без подмены на мм |
| TD | 155 | 120 | всасывающий и напорный |
| NIS | 251 | 251 | всасывающий и напорный |
| WQ (включая SHP) | 287 | 200 | напорный; присоединение всасывания не выдумывается |

Итого масса есть у 973 из 1095 моделей. Точный список 122 неподтверждённых
моделей — `cnp-physical-report.json`.

## Источники и правила

- CDM и CHLF: сохранённая выгрузка программы CNP / Eventech, параметры 11
  (масса), 29/30 (входная/выходная резьба CHLF), 121 (присоединение CDM).
- TD: официальный `TD_LLT_TD(i)_10082026.pdf`, маркировка на стр. 5,
  таблицы габаритов/массы на стр. 20–57.
- NIS: официальный `NIS_NISO_20062025.pdf`, маркировка на стр. 5,
  масса агрегатов NIS на стр. 40–43 и 97–102. Таблицы NISO и массы одной
  насосной части не использованы.
- WQ: `catalogue_WQ_120224.pdf`, таблицы на стр. 16–20, 32–33, 38, 41, 46, 48.
- SHP: официальный `SHP_021124.pdf`, стр. 11, 13, 15, 17, 19, 21.

В `cnp-physical-data.json` у каждого поля указаны источник и страница либо
исполнения программы. В индексе источников сохранены пути, ссылки и SHA-256.
`cnp-physical-reviewed.json` содержит вручную сверенные строки растровых
таблиц и исправления повреждённого текстового слоя; при разборе NIS учитываются
границы объединённых ячеек модели и мощность двигателя.

Суффиксы G, (I), (II), JY, QG, W и H не взаимозаменяемы. Суффикс числа полюсов
WQ в каталоге допускается убрать только при совпадении числа полюсов в базе.
Для 11 типоразмеров CDM125/CDM155 каталог допускает только CDMF: в карточке
показано соответствующее примечание. CDMF не подменяет обычный CDM.

Существующие значения и выбранные исполнения сохранены; цены и кривые не
изменяются. Для неопределённой массы сохраняется явный пропуск, не ноль.

## Повторное применение

Из каталога frontend:

```powershell
python scripts/apply-cnp-physical-data.py
node scripts/build-pump-card-supplement.mjs
```

Повторный запуск не меняет уже заполненные значения. Общий импорт
`merge-pump-catalogs.py` также применяет этот слой, поэтому сведения сохранятся
при следующем объединении каталогов.

Для повторного извлечения нужен Python с pypdf, локальные файлы из индекса
источников и OCR-выгрузки страниц WQ в `tmp/pdfs/cnp`. Страницы WQ рендерятся
Poppler с `-scale-to 2200`, OCR выполняет `database/ocr_cnp_pages.ps1`.
Затем запускается `scripts/extract-cnp-physical-data.py` и применение выше.
